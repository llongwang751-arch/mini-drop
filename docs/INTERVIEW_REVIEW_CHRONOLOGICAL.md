### S01-Q02｜13:03:22｜原 index 8

**问（语义整理）**：向量数据库和 RAG 有什么区别？

**参考回答**：RAG 是一套先找资料、再根据资料生成回答的流程。向量检索是其中一种找资料的方法，两者不在同一个层面。

以 AI-CRM 为例，先把知识文档提取成文本，分块后生成 embedding，把向量和正文、来源、组织及版本信息存起来。用户提问时，再把问题转成向量，检索相关片段，把片段作为引用交给模型。模型最终能否答对，还取决于资料、检索结果、权限和生成过程。RAG 也可以使用关键词或其他检索方式，不能把它直接等同于向量数据库。

### S01-Q05｜13:06:20｜原 index 12–13

**问（语义整理）**：这些检索方式为什么能加速，分别适合什么情况？

**参考回答**：原记录里提到“三种”，但没有录下前面回答的三个具体名称，我会先确认是否指精确检索、IVFFlat 和 HNSW。

精确检索逐个比较，适合小数据集，也适合做召回评测的正确结果。IVFFlat 先把数据分成若干列表，查询时只查较近的部分；查得越多，通常越接近精确结果，但耗时也会增加。HNSW 建立多层邻近图，先在上层缩小范围，再到下层找候选，代价包括建图时间和内存。当前项目使用 IVFFlat，我没有据此做过三种方案的完整性能结论。[算法取舍见 pgvector 官方说明](https://github.com/pgvector/pgvector#indexing)。

选择时，我会固定数据、过滤条件和查询集，以精确 top-k 为参照，检查召回、延迟、内存和更新成本。组织和知识源过滤之后是否仍能返回足够候选，也要测，不能只看不带权限条件的检索速度。

### S01-Q09｜13:09:34｜原 index 18

**问（语义整理）**：什么是向量？

**参考回答**：向量可以表示为一组有顺序的数。在这里，embedding 模型把一段文本映射成固定长度的数值数组，用它比较不同文本的表示是否接近。每一维通常不是人工规定的“价格”或“情绪”，不能凭某一个维度直接解释语义。

当前 AI-CRM 知识索引按 1536 维约定写入，入库时检查返回维度。问题和文档必须使用兼容的 embedding 模型与空间；只有数组长度相同还不够。相似向量意味着模型表示接近，并不保证两段文字在业务上等价，更不能代替原文证据。[入库维度与模型约定](E:/crm/AiNativeCrm-python/crm/agent/knowledge.py:21)。

### S01-Q11｜13:11:54｜原 index 22–23

**问（语义整理）**：正弦和余弦有什么区别，刚才提到的余弦与向量有什么关系？

**参考回答**：在单位圆上，一个角对应点的横坐标是余弦，纵坐标是正弦。两者满足 `cos θ = sin(π/2 − θ)`，它们不是同一个函数。

向量检索中用到的“余弦”是两个非零向量夹角的余弦：`cos θ = (u·v) / (||u|| × ||v||)`。方向相同是 1，垂直是 0，方向相反是 −1。这里比较的是表示方向，不能说分数 0.8 就有 80% 概率答对。AI-CRM 的 RPC 用 `1 − 余弦距离` 返回相似度，再结合来源、版本与业务阈值处理；它不是在比较文本向量的正弦。[项目相似度计算](E:/crm/AiNativeCrm-python/supabase/migrations/20260826140000_0181_o_acervo_e_da_organizacao.sql:445)。

### S02-Q07 · 15:07:59—15:08:09 · 你开发的基础链路具体指什么？

### S02-Q10 · 15:11:54—15:12:00 · Python迭代器与生成器有什么区别？

迭代器是实现迭代协议的对象：iter(obj)取得迭代器，next(it)取下一项，结束时抛StopIteration。可迭代对象和迭代器不同，列表可反复创建新迭代器，一个已经耗尽的迭代器通常不会自动从头开始。

生成器是创建迭代器的一种方式。函数里使用yield，调用函数得到生成器对象；每次next运行到下一个yield，局部状态保留，直到函数返回。生成器表达式也一样按需产出。它适合流式处理大文件，减少一次性装入内存，但不是自动并行，也不能无限重放。若生成器持有文件或连接，要用上下文管理或finally关闭；测试应包括空输入、部分消费、耗尽、异常传播和提前关闭。

### S02-Q12 · 15:16:47—15:16:54 · GROUP BY和HAVING有什么区别？

GROUP BY决定按哪些字段分组，HAVING过滤聚合后的组；WHERE先过滤输入行。例如查每个月销售额超过一万元，WHERE可以先限定时间段和已支付订单，再按月份分组，HAVING SUM(amount)>10000筛组。

不能简单说“HAVING是WHERE的替代”：把普通行条件放到聚合后，含义或代价都可能变；SELECT里没有聚合的字段通常必须出现在分组键里。还要确认NULL、退款、时区和金额精度口径。若要按上海月份统计，不能先按UTC月份汇总后再改显示标签，因为月初边界的订单已经分错组。

### S02-Q13 · 15:17:45—15:27:39 · 合并两个数组并得到有序数组，怎么实现和验证？

记录说明：保留真实代码考核；原始题面/输入未导出，不假造完整题干。

原记录只保留了“两个数组合并后有序”，没有输入约束。我会先确认两个输入是否已经有序、是否要求原地、是否保留重复值。若都是升序，双指针每次取较小元素，时间O(m+n)、额外空间O(m+n)；若输入无序，下面算法就不适用，应合并后排序或先各自排序。

```python
# 假设：输入均为升序整数序列；保留重复值；不修改输入。
def merge_sorted(a, b):
    i = j = 0
    result = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i]); i += 1
        else:
            result.append(b[j]); j += 1
    result.extend(a[i:])
    result.extend(b[j:])
    return result
```

验证不能只看示例。至少检查双空、单空、重复值、负数、两段完全不交错及长度悬殊；再断言结果等于sorted(a+b)、长度为m+n、输入未变。本轮提供的是根据残缺题干重建的参考实现，未声称复原当时隐藏测试或已执行此代码。

### S02-Q14 · 15:28:22—15:31:55 · 按月份统计销售总额，SQL怎么写？

记录说明：“Circle”疑似SQL的ASR误识别，只确认月/销售总额，参考SQL显式声明假设。

```sql
-- 参考示例，不是导出的原题SQL；$1=业务时区，$2/$3=时间边界。
SELECT date_trunc('month', created_at AT TIME ZONE $1)::date AS month,

FROM orders
WHERE created_at >= $2 AND created_at < $3
GROUP BY 1
ORDER BY 1;
```

采完后，Agent 计算文件大小和 SHA，上传 RAW，再调用 NotifyResult。Core 验收当前轮次、状态及协商制品元数据，原子登记 COLLECTED、分析 Job 和事件；它不下载 RAW 复算真实 SHA。Python Analyzer 领取 Job，下载后核实际字节与 SHA，解析、上传结果，再凭有效租约发布数据库引用。前端读 REST 状态，SSE 触发刷新，完整调用树交给 Worker 校验和布局。

每段成功含义不同：HTTP 创建成功不表示采样已经启动，COLLECTED 不表示分析成功，文件已上传也不等于结果已发布。失败恢复先确认停在哪一段，不能一律重新采样，因为那会换成另一个现场窗口。

### S03-Q18｜16:59:48–16:59:54

**问（语义整理）**：Agent 平台最难的地方，怎样解决？

**参考回答**：一处实质难点是“恢复图状态”和“外部动作是否发生”不能混为一谈。模型已经返回、消息已经入队或业务已经修改，随后 checkpoint/回执写失败，重跑节点可能重复付费或重复动作。因此实现把图 checkpoint 与效果 journal 分开，先记 started 意图，完成后保存返回值；已完成可复用，只有 started 而无结果时要求核对，不盲目重做。

另一个实际窗口是 LangGraph 的 put_writes 早于 checkpoint 主体到达。适配器把写入按 checkpoint_id 暂存在持久 pending_writes，主体提交时合并，按 task/index 去重；ainvoke 排空后台写入后才 compact，仍有孤立写入就拒绝剪掉恢复证据。所有写仍核租户、领取身份、取消与客户隐私状态。

这套机制不宣称数据库与模型、渠道形成跨系统原子事务，而是在确认、复用与未知三种状态之间保留可恢复含义。回归通过故障注入检查模型调用次数、业务写次数和恢复后的状态，本次只是读现有用例，没有重新运行。

### S05-Q08 · 17:21:30—17:22:00 · 多接口场景怎样稳定执行，并保证数据状态一致？

**问（语义整理）**：单项指标还是总分？权重和评分具体怎么算？

**参考回答**：当前 Python 实现的 revision 8 有七项：任务完成 25、答案质量 20、知识与证据 25、工具可靠性 20、策略合规 20、效率 10、协作 10。这些是相对权重，总和为 130，不是相加必须等于 100 的百分比。每项 pass 计 100、needs_review 计 50、fail 计 0；not_run 不参与分母。总分对实际有分数的维度加权归一化。
