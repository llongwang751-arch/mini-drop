  21. 21## 状态与采集
  22. 22
  23. 23状态值字符串，见SQL CHECK。kind字符串来自task-kinds.json。ID REST JSON统一字符串（保留浏览器精度）。所有时间ISO8601 UTC，界面Asia/Shanghai。
  24. 24
  25. 25TaskAttempt是一次执行。手动重试同一Task新增attempt，旧制品事件保留。当前attempt为MAX(attempt)。任务取消后晚到NotifyResult不得覆盖；AnalysisJob只接受该任务当前attempt且collection=COLLECTED。所有变更写task_events。
  26. 26
  27. 27API创建 task + attempt + event + outbox同事务。outbox dispatcher生成raw对象key与600秒PUT URL（每次dispatch刷新），写attempt.raw_upload_url，再gRPC CreateTask。Server幂等将CREATED→QUEUED，不创建Task。Server心跳从DB持久化任务里取QUEUED并标DELIVERED；任务描述从DB读取attempt、params、presigned URL，1台Agent最大1并发。
  28. 28
  29. 29Server Progress接收RUNNING/UPLOADING（合法单向转换），NotifyResult成功事务写RAW Artifact、COLLECTED、attempt终态、pending AnalysisJob与event。RAW名称、内容类型、格式及分析pipeline来自TaskKind真源，不把所有输入当作folded；key为raw/tasks/{taskid}/attempts/{attempt}/{raw_name}。SHA256小写64位。BINARY附件的短期PUT目标保存在attempt.upload_targets；Agent仍不持有长期对象存储凭据。
  30. 30
  31. 31支持采集manifest的Agent在注册labels声明`collection_manifest_version=1`。仅在该协商成立时Server下发并要求`MANIFEST/collection_manifest_v1`，固定名`collection-manifest.json`、Content-Type application/json、最大65536字节，key为`manifest/tasks/{taskid}/attempts/{attempt}/collection-manifest.json`；旧Agent不会因为不认识新增制品而失去兼容。manifest在数据制品PUT成功后生成一次，记录实际起止、版本、去敏参数、object key、size、SHA256及不作内容hash解释的opaque ETag；不包含URL、凭据、目标文件路径或原始stderr。恢复沿用已持久化的同一份字节，不重新采集或递归记录自身hash。采集MANIFEST与Analyzer结果manifest是独立制品，不能互相覆盖。
  32. 32
  33. 33Agent perf record实际采样→perf script解析为folded；PROC_CPU每线程/proc CPU tick差→ `process;thread-name`计数，结果和建议须明确仅线程级。绝不把procfs数据宣称perf采样。内置CPU workload可作为pid供验证，进程列表在resources.processes里仅提供可采样的受控进程。不使用shell。
  34. 34
  35. 35离线导入：17种非COMPOSITE类型均可使用通用import文件；IMPORT_COLLAPSED另保留collapsed_text（最多2MiB）。API上传后同事务写RAW/附件、COLLECTED、分析job和event，不dispatch Agent。通用文件导入先于旧文本分支校验，因此IMPORT_COLLAPSED也可直接导入文件。所有导入保存params.source=import，分析摘要source=import，现场时长/频率为null，不把文件内部时序当作平台现场采集承诺。明确标识的示例由用户主动导入，不预置假任务。

  78. 78部分分析结果：
  79. 79
  80. 80- 下列16KiB限制针对紧凑UTF-8 `data`正文，标准`request_id/data/error` envelope另留1024字节；partial接口以JSON直接编码`< > &`，浏览器仍仅作React转义文本渲染，不把符号当HTML。
  81. 81
  82. 82- GET `/tasks/:id/partial-result`沿用Task read授权，仅Task为`collection_status=COLLECTED`、`analysis_status=FAILED`，且当前failed job、最新采集attempt、当前analysis run、最新ready RAW id/SHA与检查点全部吻合时返回；没有可用当前检查点返回409 `PARTIAL_RESULT_NOT_READY`。`/result`仍只返回成功分析，partial不进入AI或Compare成功路径。
  83. 83- 正文遵循[`contracts/partial-result.schema.json`](../contracts/partial-result.schema.json)：`schema_version:1,completeness:'partial',task_id,attempt_id,analysis_job_id,analysis_run,input_artifact_id,input_digest,kind,completed_stages,missing_stages,summary,top_functions`，不允许额外键。ID为正int64十进制字符串；run为1..2147483647；总UTF-8 JSON≤16KiB、深度≤6；数值finite、非负且JS安全，unique_stacks/node_count≤100000、max_depth≤128、百分比≤100。Top K≤20，name最多160个UTF-8字节且无Unicode类别C字符，仅任务授权用户可见并作为转义文本；symbol_sha256对应原完整符号。source使用契约枚举，unit为`^[A-Za-z0-9_.-]{1,32}$`，producer将未知来源/不合单位语法映射unknown。示例为明确synthetic导入fixture：[`partial-result-v1.json`](../contracts/fixtures/partial-result-v1.json)。
  84. 84- `completed_stages`固定`['input_verified','parsed']`，`missing_stages`固定`['diagnostic_rules','result_artifacts','final_commit']`；后者指这份快照未包含的成果，不断言后续阶段从未执行。只保留校验完成的摘要、Top K和计数，不复制完整flamegraph、raw/collector metadata、原tool report、内部工作路径、对象key/URL或建议正文。
  85. 85- Task详情可选`analysis_identity:{analysis_job_id,analysis_run,input_artifact_id,input_digest}`锚定当前job/run与最新采集输入，浏览器同时绑定Task.version并校验全部标识；缺identity不读取partial。检查点沿用`analysis_jobs.result` JSONB，由当前owner/run/未过期lease及输入绑定原子写入；新claim清空，失败可保留本run，成功完整结果覆盖。手动reanalyze原有run归档和清空继续生效，绝不回查历史run作当前partial。inline检查点不是INTERMEDIATE对象，不假称已有三天对象删除策略；无新增SQL migration。

  160. 160## AgentScope internal runtime contract (2026-10-20)
  161. 161
  162. 162`contracts/agent-runtime-v1.json` defines the private Go ↔ Python control
  163. 163protocol for the optional `AI_AGENT_BACKEND=agentscope` backend. AgentScope
  164. 1642.0.10 runs planning, diagnosis and source-repair ReAct loops; Go owns task
  165. 165state, authorization, tool schemas, evidence and final acceptance. Existing
  166. 166HTTP routes, SQL migrations and protobuf field numbers are unchanged.
  167. 167
  168. 168Two separate Unix sockets authenticate the real process UIDs with
  169. 169`SO_PEERCRED`. Their producer directories use owner UID 10001/10002, group
  170. 17010003 and mode 2750; each consumer mounts the other socket directory read-only.
  171. 171Each run receives an ephemeral private capability, distinct from its persisted
  172. 172public UUID. Capabilities are revoked on cancellation or completion and never
  173. 173become model input or report data. Callback IDs are idempotent only for an
  174. 174identical canonical request; different content reusing an ID terminates the run.
  175. 175
  176. 176Go reserves every actual model call before provider I/O, checks all tool calls
  177. 177against phase schemas and domain fences, and accepts only its own validated
  178. 178JSON result. Historical protocol1 diagnosis keeps one initial evidence plus
  179. 179at most seven callbacks and a 4+1 model budget. The SQL010 extension below
  180. 180defines protocol2 budgets, durable recovery and explicitly charged provider
  181. 181retries. SDK automatic retries and autonomous context compression remain
  182. 182disabled. No automatic fallback to `legacy` occurs after a runtime error.
  183. 183
  184. 184Successful diagnosis and repair reports include server-derived `agent_runtime`
  185. 185metadata (framework/version/class, public run UUID, model/tool counts, elapsed
  186. 186milliseconds and optional token usage). Planning appends equivalent metadata as
  187. 187an `agent_runtime` trace step, outside the business tool budget. Model-authored
  188. 188runtime metadata is rejected. Runtime metadata proves execution and counts;
  189. 189it does not certify the semantic truth of a model explanation.
  190. 190
  191. 191The Python runner preserves the fully validated raw JSON value accepted by Go,
  192. 192including decimal/exponent notation, negative zero and precision. It must not
  193. 193decode and re-encode that value through binary64 before returning it. Go's
  194. 194strict canonical result equality remains authoritative. A non-200 runtime
  195. 195response may include only a fixed allowlisted error code and optional bounded
  196. 196private stage/kind/counters defined in the manifest. Unknown fields or SDK
  197. 197message text are rejected; result mismatch and metadata mismatch have distinct
  198. 198fixed error codes. These diagnostics are not model input or report content.
  199. 199
  200. 200Cancellation and lease/authorization revocation close the model/callback
  201. 201connection. The source-test broker also observes caller disconnection and
  202. 202stops only the verified job container by immutable Docker ID. SQL010 recovery
  203. 203restores validated visible boundaries under the remaining persisted budget;
  204. 204token-level framework continuation is not a contract.

  229. 229### 报告协议2与业务观测
  230. 230
  231. 231模型最终输入对象只接受 `{report_version:2,facts,hypotheses,verification_requests}`：facts为1–24项，hypotheses为1–4项，verification_requests为1–3项。模型不能填写summary、可信标签、engine、knowledge或agent_runtime。
  232. 232
  233. 233- 事实输入为 `{id,evidence_id,path,operator,value,unit}`。E编号必须属于当前实际工具返回；path仅允许预定义JSON Pointer，operator仅 `eq/count/count_positive_self`。Go按精确数值、标量、单位和来源核对，再生成 `description`。`count_positive_self`只计算已返回Top表中的正self项目，不证明完整树的唯一叶帧。
  234. 234- RESOURCE_SNAPSHOT的E1增量只投影分析器实际聚合：`resources.schema_version=1`、固定source、sample_count、scope、七种可用peaks及固定units；不包含raw samples、PID或dmesg。事实只允许`/resources/sample_count`及七个峰值的eq路径，缺失不补零，样本数1–3600、计数/字节整数不超过2^53−1。资源CPU多核百分比独立限制0–100000，不放宽函数热点的0–100。程序使用资源摘要，不把零函数权重等同没有资源观测；峰值与主机可见内存不证明持续压力、整容器用量或根因。

  236. 236- 报告拒绝反馈仅由服务包内专用类型生成，序列化前重新核对reason、分区、索引、字段、工具名与单位白名单；不会回显通用错误详情、任意path/value或未知引用。假设前提、事实引用和标量误用count均可明确定位；不自动改写错误报告、不添加工具/模型预算，格式轮仍禁止工具。
  237. 237- py-spy空栈适配只用于python_cpu_v1/PYTHON_CPU/folded和当前采集attempt关联的可信runner_metadata，用户制品自报或import不触发。未知栈/帧使用固定占位符保留全部权重，sections.sampling_quality及metadata记录固定计数。Go核source、单位、总权重与两份计数一致后才投影质量；未知占位正权重不能支持cpu_hotspot。Repository使用不与attempt整数列冲突的行别名读取runner_metadata；重新分析保留原failed analysis_run归档。

  239. 239- `query_business_signals`仅接收 `{service_ref:'S1'..'S8',signal:'metrics'|'logs'|'traces'|'changes'}`；`inspect_service_topology`只接收空对象。S1为根服务，完整登记邻接排序形成其余固定别名；无权服务保留内部空位而不重绑其他别名，不返回真实身份。
  240. 240- 业务查询的 `window` 优先使用绑定attempt中Agent/helper记录的完整整数 `collection_started_unix_ms` / `collection_finished_unix_ms`，须位于有界attempt执行区间内，`window_scope=collector_execution`；它不是逐个sample的采样时间戳。仅两项均未记录的旧任务回退attempt执行区间并标 `attempt_execution`，可能含准备/上传。原起止各扩展一分钟仅以 `context_window` 展示，`context_queried=false`，不发给源或混入本次查询。缺失执行边界、坏/单项/反序/越界collector时钟返回 `available:false/reason:collection_window_unknown`，不补正常零值，不用创建或分析完成时间替代。数据源版本改变、当前撤权或来源重分析仍阻止旧快照复用。固定预聚合查询自身的回看语义由登记源决定，查询时间边界不等于重建其全部底层请求；本轮精确请求窗口回归使用Drop adapter。
