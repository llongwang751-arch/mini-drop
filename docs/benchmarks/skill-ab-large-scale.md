# Mini-Drop 大规模 Skill A/B 与稳定性测试

## 这次实际测了什么

运行入口：

```bash
python scripts/run_scaled_skill_ab.py
```

评测器从冻结的 12 个 Skill 和 16 个人工标注基础 Case 出发，用固定随机种子生成 1200 个 Case：

- 720 个正例改写，覆盖中英文前后缀、术语替换、语序和无关噪声；
- 240 个伪相似负例，检查相似症状会不会错误复用；
- 120 个环境漂移例，检查 staging Skill 会不会套到不兼容环境；
- 120 个能力漂移例，检查 Agent 缺少 Collector 或权限时会不会继续使用 Skill。

每个 Case 同时经过两种策略：

- A：不使用 Skill，只采用按故障类别固定的静态规则先验；
- B：启用生产实现中的硬过滤、BM25、本地特征向量、结构化上下文和歧义拒绝。

主指标是 `symptom_to_root_cause_route_prior_accuracy`，含义是系统有没有选中正确的根因取证路线先验。它不是证据验证后的真实根因准确率。

## 当前结果

机器可读报告：`artifacts/skill-ab-large/report.json`

可读报告：`artifacts/skill-ab-large/report.md`

本次固定数据和种子下：

- 无 Skill：240/1200，20.00%；
- 启用 Skill：1175/1200，97.92%；
- 增加 77.92 个百分点；
- 只看 720 个正例的根因路线 Top-1：33.33% 到 97.22%，增加 63.89 个百分点；
- 正例中有 20 个保守拒绝，没有选错 Skill；
- 负例中有 5 个误激活，误激活率 1.04%；
- 环境漂移和能力漂移均全部拒绝。

这组数字不能写成“生产根因准确率从 20% 提升到 97.92%”。它证明的是生成式扰动集上的路线先验选择能力。

## 为什么还要做阈值校准

当前生产检索门槛是总分 0.35、歧义差值 0.04。本次网格搜索将 Case 按 ID 固定拆成训练和留出验证集，并对误激活施加更高惩罚。

生成集上推荐的候选值是总分 0.60、歧义差值 0.10；留出集准确率 96.58%，负例误激活为 0。这个结果只能作为候选配置，不能直接替换生产值。最终门槛需要使用真实诊断的 VERIFIED 报告和人工反馈重新校准。

## 长时间稳定性测试是什么

长时间稳定性测试也叫 soak test。它让系统在数小时或一天内持续处理请求，关注的是“长时间会不会坏”，而不是单次回答是否正确。需要观察：

- 进程内存、容器重启次数和数据库连接是否持续增长；
- Task、Attempt、租约和 AnalysisJob 是否出现卡死或重复执行；
- SSE 重连后是否丢事件或回退版本；
- 模型超时、Agent 离线和 MinIO 短暂失败后能否恢复；
- 同一固定输入的 Skill 决策是否发生非预期漂移。

当前脚本已经提供检索决策层稳定性循环：

```bash
python scripts/run_scaled_skill_ab.py --stability-seconds 21600
```

`21600` 秒是 6 小时。当前已完成的是 64 秒、6000 次检索决策的短时验证，错误和决策漂移均为 0。它还不是 Go、PostgreSQL、MinIO、C++ Agent、Analyzer 和模型供应商全部参与的 6 小时全链路 soak。

## 线上 A/B 校准是什么

线上 A/B 是将真实新诊断稳定分成两组：

- A 组关闭 Skill，走规则 Planner；
- B 组启用 Skill，其余模型、预算、故障类别和时间窗口保持一致。

分组必须按 `diagnosis_id` 或服务做稳定哈希，同一个诊断不能在两组之间跳动。脚本中的 `assign_ab_arm` 已实现 SHA256 固定分桶，Shadow A/B 报告用于先检查统计链路。

生产 A/B 应记录：Skill 是否命中、命中版本、最终报告是否 VERIFIED、人工 correct/partial/wrong、工具调用数、诊断耗时、失败率和负迁移。只有真实结果样本达到预设数量并通过置信区间检查，才能调整门槛或扩大 B 组流量。

RCAEval 当前公开 9 个数据集、735 个真实故障 Case；Hugging Face 版本约占 3.4 GB。要得到外部数据上的真实根因准确率，需要先实现 `metrics/logs/traces -> Mini-Drop Evidence` 适配器，再冻结训练、校准和测试切分。不能直接拿文本标签喂给 Skill，否则会发生答案泄漏。
