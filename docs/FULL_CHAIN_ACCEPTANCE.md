# AGI-saber → Mini-Drop 全链路验收

初次使用可先按 [图文演示步骤](DEMO_WALKTHROUGH.md)走一遍页面，再用本页逐项判定是否通过。

本页对应 2026-09-23 云端实际发布。它把“业务操作跑通”“业务慢阶段定位”“AI 根因验证”“恢复”分开验收。入口为 `https://120.24.187.205`；平台登录凭据和办公助手账号各自保存在私有配置中，**不要把硅基流动 API Key 填进网页或提交到 Git**。2026-09-24 已获授权清除旧百万字验收文档；此后新上传 20,000 字图文演示文档，当前共 2 篇活跃文档、139 个 RAG 分块，重启后的向量健康样本语义检索正常。要复验百万字链路，请从第 2 步**重新上传**，不要用已删除旧文档的请求记录代替本次上传。

## 页面手工验收

1. 登录 Mini-Drop，打开“AI 诊断 → 选择服务”，选“AGI 办公助手后台”。先点击“检查当前状态”。应看到真实 PID、进程 CPU/RSS/线程/FD，以及本次观测窗口结论；没有采到系统指标时必须显示无法判断，正常窗口不能写成“根因已验证”。展开可查看证据与排查树。
2. 点击“打开办公助手”，使用办公助手自己的账号登录。在原页面上传约 100 万字的 UTF-8 `.txt` 文档。等待页面显示“上传完成”和分块数。当前样本应约 7,701 块；具体数量取决于文本内容与分块配置。若网页、网关或浏览器先超时，记录失败，不以后台最终写入代替页面通过。
3. 返回 Mini-Drop，刷新服务，在“关联业务请求”选择**刚上传**的“文档分块入库”及其 request_id；历史请求排在后部时可输入实际字数筛选。页面应先显示字数、分块数、已入库向量数、总耗时、最大耗时阶段、进程 CPU/RSS、服务组 CPU/内存峰值与**当时**的限额。展开检查接收解析、分块、向量化、向量库写入、索引。数字来自该请求的后台埋点；未采到的字段显示缺失。若 Embedding 失败或向量数少于分块数，必须如实显示，不能称向量检索通过。9 月 23 日的旧 `999,999` 字请求可能仍在 24 小时观测窗口内，但其文档已清除，只能查历史计时。
4. 选中同一请求，点击“检查当前状态”；打开体检报告和排查树。业务慢阶段可在顶部明确为“向量化”或“索引入库”（取决于本次真实耗时）。进程取证属于当前复现窗口，不能冒充历史上传时的独立证据。报告若为 `INSUFFICIENT_EVIDENCE`，仍按原样展示；“已定位慢阶段”只表示业务分段计时定位，不等于 VERIFIED 根因。
5. 回到办公助手对刚上传文档提问，检查回答与检索证据来自新文档。Mini-Drop 选择对应“知识库问答”请求，检查查询改写、向量化、检索、重排、生成实际阶段；未执行阶段保持空值。后台需确认 `retrieval_mode=semantic` 和非零候选，排除仅词法回退。
   如要验收重启持久化，等待正在运行的诊断结束后重启 `agi-office-backend.service`，再提同一问题。网页应继续答对、后台仍为 `semantic`；Mini-Drop 的旧上传 request_id 仍可选，新问答显示新 PID。旧 PID 只是历史记录，不可作为当前采样目标。
6. 如需演示故障，在“选择服务”的 AGI 办公助手卡片点击“运行三段验收”：页面依次发起正常 → 带标记的受控慢检索 → 撤销后请求。故障只给第二次问答检索阶段增加 2,500 ms 延迟，页面应分别显示三个真实请求及耗时、同进程/版本，以及“受控慢检索已定位并撤销”。第三次请求不带注入标记；没有全局故障开关。撤销注入不代表完成代码修复，AI 报告仍以 Evidence Gate 为准。“故障广场”的其他 21 项场景可做启停演示，但不要把启停成功说成全部根因通过。

## 运维与自动验收

在仓库根目录运行 `python -m pytest -q`、在 `web/` 运行 `npm test -- --maxWorkers=2 --testTimeout=15000` 和 `npm run build`。云端核对 `systemctl is-active agi-office-backend.service`、`systemctl show agi-office-backend.service -p MemoryMax -p NRestarts`、平台四容器健康状态和 `/api/healthz`。服务组内存限额应为 1610612736 字节（1.5 GiB）；这是办公助手 cgroup，不是主机 RAM。业务状态目录、Milvus Lite 向量库、平台 PostgreSQL/MinIO 均不得因发布或回滚被清空。硅基流动凭据仅由 root 私有 `/etc/agi-office/backend.env` 注入。
请求观测文件 `/var/lib/agi-office/mini-drop-observations/requests.json` 当前应为 `mini-drop.office-observations.v2`，最多 100 条、只包含白名单字段；Mini-Drop 只展示近 24 小时的记录。重启后核对 Mini-Drop 请求列表 `AVAILABLE`、非法记录数 0、历史上传仍在；不要把历史请求的应用自报 PID 当作当前 Native Agent 的 PID。

验收依据见 [长文档报告](../reports/business-acceptance/long-document-ingest-20260923.md)。若远程 Embedding 服务不可用，上传可以保留词法检索作为降级，但必须标出向量失败，**不能**将 `upload 200` 当成向量链路通过。若恢复后仍有注入标记、服务重启/OOM、网页超时、请求无法在 Mini-Drop 选择，均判为链路失败。重跑时保留原报告和 request_id，不覆盖失败证据。
