# AI 诊断多轮反证闭环

更新时间：2026-07-29

## 1. 目标

本轮把原先“生成一份诊断结论后结束”的流程扩展为受预算约束的多轮闭环：

```text
低风险事实采集
  -> 结构化证据与初步结论
  -> 从结论中选择一个 FALSIFY 反证动作
  -> R2 人工审批
  -> Agent 执行真实采集
  -> Analyzer 生成结构化产物
  -> 证据回流并重新计算假设
  -> 达到轮次、风险或时长上限后停止
```

系统不会为了得到“看起来完整”的答案而自动执行深度探针。所有 R2 反证采集仍然需要单次人工审批，失败也会作为真实运行结果保留。

## 2. 核心数据设计

### 2.1 证据目的

每个诊断动作和探针显式标注：

- `VERIFY`：确认环境、目标和基础事实；
- `SUPPORT`：寻找支持某个假设的证据；
- `FALSIFY`：主动寻找能够推翻当前假设的证据。

### 2.2 诊断轮次

`ProbeExecution` 持久化 `round_index`，诊断预算增加 `max_diagnosis_rounds`：

| 策略 | 最大诊断轮数 | 设计目的 |
|---|---:|---|
| `production_safe` | 1 | 生产环境优先控制副作用 |
| `staging` | 2 | 允许一次审批后的反证验证 |
| `development` | 3 | 用于开发和故障注入实验 |

每轮分析后同时持久化：

- 已完成分析轮数；
- 已使用反证探针数；
- 假设分数、支持证据、反对证据和历史；
- 结论版本；
- 审计事件和停止原因。

## 3. 停止条件

编排器不会无限循环。以下任一条件满足即停止继续规划：

1. 达到 `max_diagnosis_rounds`；
2. R2 中风险探针预算耗尽；
3. 总采集时长预算不足；
4. 没有新的、未执行过的反证探针；
5. 任务失败或结构化证据不足；
6. 用户拒绝审批或取消诊断。

停止原因写入审计事件，并通过 Prometheus 计数器暴露：

- `mini_drop_ai_diagnosis_rounds_total`
- `mini_drop_ai_diagnosis_stop_conditions_total`

## 4. 运行时验收

本轮在 Windows Docker Desktop + WSL2 环境进行了真实链路验收。

### 4.1 范围保护

首次请求故意使用与 Agent 不一致的 `host_id`，诊断进入
`NEEDS_SCOPE_CONFIRMATION`。这证明系统不会猜测 PID，也不会把任务错误地下发到其他主机。

### 4.2 真实低风险采集

使用在线 Agent 的真实主机标识和 PID 1 创建 `staging` 诊断：

- 诊断会话：`diag_session_20260729_063125_8cd7f693`
- 首轮探针：`host_process_metrics`
- 对应采集器：`sys_metrics`
- 真实任务：`task_20260729_063125_0d4d88`
- 结果：`DONE`
- 探针结果：`COMPLETED`

低风险证据不足以区分候选根因后，系统自动生成
`process_cpu_profile` 反证探针，并进入 `WAITING_APPROVAL`。

### 4.3 人工审批与真实失败保留

审批 `step_10024e1689f475` 后，系统创建真实 perf 任务：

- 任务：`task_20260729_063222_005319`
- 证据目的：`FALSIFY`
- 风险等级：`R2`
- 结果：`FAILED`
- 会话终态：`PARTIAL_COMPLETED`

失败原因来自 Docker Desktop 内核的 perf 运行环境，而不是用模拟结果替代。
系统保留第一轮有效的系统指标、第二个探针失败状态和“不足以可靠判断根因”的结论，
符合“证据不足时明确降级”的设计要求。

运行快照属于一次性本地验收产物，不纳入仓库。该链路由自动化测试和本节记录的
诊断、任务及探针 ID 复现，避免长期保存过期会话数据。

- 全量 Python 测试：`419 passed`

## 6. 当前边界

自动化测试已经验证“两轮均成功”时会产生两个结论版本并正确停止；当前
Docker Desktop 运行验收则验证了“第一轮成功、第二轮深度采集失败”的降级路径。
要验证真实 perf/eBPF 反证成功链路，应在允许 `perf_event_open`、挂载
`debugfs/tracefs` 且具备相应 capability 的原生 Ubuntu 环境执行。
