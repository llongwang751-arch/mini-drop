# 诊断策略自进化测试集说明

## 1. 评测目标与案例组成

固定数据位于 `tests/fixtures/diagnostic_skill_evolution/cases.json`。测试集离线比较无技能基线与启用技能后的系统输出，覆盖策略复用、拒绝负迁移、漂移降级、错误反馈隔离、版本回滚和污染证据拒收。

| `incident_family` | 数量 | 验证目标 |
|---|---:|---|
| `SIMILAR_INCIDENT` | 5 | 相同根因族能复用已验证路线 |
| `MISLEADING_INCIDENT` | 4 | 表象相似但根因不同的事故拒绝套用旧策略 |
| `ENVIRONMENT_DRIFT` | 2 | 环境、采集器或权限变化时安全降级 |
| `WRONG_FEEDBACK` | 2 | 连续错误反馈触发隔离且阻止后续复用 |
| `VERSION_ROLLBACK` | 1 | 新版本失败后恢复上一已发布版本 |
| `CONTAMINATED_EVIDENCE` | 1 | 缺少 provenance 或 integrity 的证据不得沉淀技能 |

每条案例至少包含：

- `case_id`
- `incident_family`
- `symptom`
- `environment`
- `available_collectors`
- `expected_root_cause`
- `expected_action`
- `forbidden_action`
- `oracle_refs`
- `difficulty_reason`

生命周期案例另带状态、版本或证据完整性 Oracle。测试会校验字段、类型、唯一 ID、非空 Oracle 和精确的 5/4/2/2/1/1 构成。

## 2. 数据隔离与防止自证

`source_diagnosis_ids` 只用于生成技能，不属于最终 15 条评测样本。测试强制来源诊断 ID 与 `case_id` 不重叠。

评分器位于 `server/app/drop_insight/skill_benchmark.py`，不调用规划器或 matcher，也不读取技能自己的门禁结论。系统先产生 observation，评分器再用冻结 fixture Oracle 判分。重复 ID、计划外 ID、负工具调用数和非法 observation 会直接被拒绝；缺失 observation 判失败，但不会以零调用或零耗时改善均值。

## 3. 输出与指标

`compare_benchmark_runs` 始终输出：

- `baseline`：未启用策略的结果；
- `skill_enabled`：启用策略及生命周期机制后的结果；
- `delta`：通过率、代理工具调用数和负迁移率差值。

每个比率指标都带 `numerator`、`denominator`、`value` 和 `status`：

| 指标 | 计算方式 |
|---|---|
| 根因准确率 | 根因与 Oracle 一致的实测数 / 提供实测根因的案例数 |
| 误导反例拒答率 | 正确 fallback 的误导案例数 / 误导案例总数 |
| 环境漂移正确降级率 | 正确 fallback 的漂移案例数 / 漂移案例总数 |
| 平均工具调用数 | 已提供调用数之和 / 已提供调用数的 observation 数 |
| 平均诊断耗时 | 已提供真实耗时之和 / 已提供真实耗时的 observation 数 |
| 负迁移率 | 禁用动作、应降级却应用技能、相对 baseline 从通过退化为失败或代理成本上升的案例数 / 全部案例数 |
| 相似事故收益率 | 通过 Oracle 且代理工具调用数低于该案例 baseline 的相似案例数 / 相似案例总数 |
| 隔离成功率 | 达到隔离阈值且技能状态为 `QUARANTINED` 的案例数 / 预期进入隔离状态的案例数 |
| 回滚成功率 | 新版本记录失败后恢复版本符合 Oracle，且后续路由命中恢复版本的案例数 / 回滚案例总数 |
| 证据引用完整率 | 显式验证引用存在且可追溯的案例数 / 提供引用有效性观测的案例数 |

离线 fixture 中的工具调用数是确定性路线的代理成本，标记为 `PROJECTED`。没有真实系统输出时，根因准确率和诊断耗时返回 `NOT_MEASURED` 与 `null`，不得将 fixture 中的答案回填为系统实测结果。

## 4. 执行方式与结果解释

运行：

```bash
python -m pytest -q tests/test_diagnostic_skill_benchmark.py
```

测试只使用内存 SQLite，不访问公网、Docker 或云端。`DETERMINISTIC_SKILL_EVOLUTION_REPLAY` 可以验证：

- 独立样本上的路由复用和反例拒绝；
- 环境边界 fallback；
- 两次错误反馈后的真实 `QUARANTINED` 状态及后续停用；
- v2 记录错误结果后的真实回滚状态，以及后续路由是否命中恢复的 v1；
- scorer 能否暴露伪相似误用、能力漂移、污染证据、缺失输出和相对 baseline 的负迁移。

它不能证明：

- 真实故障根因已经被准确定位；
- perf、eBPF、JVM 等采集器在目标 Linux 环境真实执行成功；
- 真实诊断耗时或真实工具调用成本下降；
- 长期运行不存在新的分布漂移。

这些能力必须由来源事故之外的 Linux Campaign 在相同环境、预算和冻结 Oracle 下补充验证。

## 5. 已关闭缺口与剩余边界

本轮已将此前三条严格预期失败转为普通验收测试：

1. 伪相似事故拒绝：运行时会比较技能类别、当前专业 baseline 路线与显式 `suspected_subsystem`；network、storage、database、JVM 等与 CPU 技能冲突的路线会保持原计划且不写入 activation。固定测试中的四条同类别反例均正确降级。
2. 能力/权限漂移：当 target 显式提供 `collector_capabilities` 或 `permission_denied` 时，已学习工具只有在所需能力可用且未被拒权时才可选择；没有可执行学习路线时保持 baseline。固定测试中的两条漂移案例均正确降级。
3. 污染证据拒收：候选沉淀前会校验引用存在性、诊断与 hypothesis 归属、严格 envelope schema、重新分类结果及已保存分类；缺失引用、provenance 或 integrity 无效的证据不能创建候选。人工正确反馈也必须属于当前报告。

离线 benchmark 当前验证 15/15 合同通过、误导反例拒答 4/4、环境漂移降级 2/2、负迁移 0/15。污染案例的证据引用完整率仍为 0/1，这是拒绝不可追溯引用的预期观测，不代表候选被错误接纳。

完整生产策略预检仍不在该离线回放范围内。为兼容现有调用，target 未携带 capability metadata 时不会推断采集器不可用；风险、预算、绑定和审批等完整 `PolicyContext` 校验仍应由服务边界负责。上述结果也不改变第 4 节所列真实 Linux Campaign 验证要求。

## 6. 与基础测试集交付格式对齐

亮点测试集 `v5` 已不再只是仓库内 fixture 和前端统计，而是按基础测试集的盲测思路拆成交付物：

- 公开题面：只包含症状、环境、目标和可用采集器，不含期望动作、根因和禁用动作；
- 私有 Oracle：保存标准根因、允许/禁止动作、降级模式、隔离和回滚预期，仅供裁判评分；
- 干预事件：错误反馈和已验证失败按步骤释放，不提前写入题面；
- 统一契约：约束 observation 字段、工具调用上限、拒答和安全边界；
- 来源锁与冻结哈希：固定原始 fixture 和关键评分文件，避免评测后改题；
- 独立评分器：根据私有 Oracle 计算通过率和负迁移率；
- 交付复核：检查文件哈希，并阻止 Oracle 字段泄漏到公开题面。

重新生成：

```powershell
python scripts/package_skill_evolution_delivery.py
```

生成两个压缩包：

```text
artifacts/deliverables/Mini-Drop策略自进化亮点测试集-20260825-v5.zip
artifacts/deliverables/Mini-Drop策略自进化亮点测试集-20260825-v5-盲测公开包.zip
```

完整包由裁判保管；盲测公开包才交给待测系统。当前交付校验结果为：完整包 15 个案例、7 个冻结文件通过；公开包 15 个案例、6 个冻结文件通过，且未包含私有 Oracle 和参考报告。
