# Skill 混合检索说明

## 为什么替换旧规则

旧实现只看故障类别、环境和服务：类别相同 650 分，环境相同加 200 分，服务相同加 100 分，700 分以上直接命中。同一服务下的 CPU 热点、磁盘写回和连接池耗尽可能拿到完全相同的分数，保存下来的 `query_terms` 没有真正参与选择。

## 当前检索链路

1. 先做硬过滤。类别、环境、规划路线、权限或 Agent capability 不兼容时，Skill 不进入候选集。
2. 再做软排序：`30% × 结构化上下文 + 45% × BM25 + 25% × 特征向量余弦相似度`。
3. 最后过门槛。首名低于 `0.35` 时拒绝；前两名总分差小于 `0.04`，且 BM25、向量两项都没有拉开 `0.08` 时，也拒绝自动套用。

BM25 适合服务名、指标、系统调用和函数名等精确证据。向量项使用 512 维、有符号哈希的字符 n-gram 与有限诊断概念特征，能够处理拼写变体和局部表达变化。激活记录会保存 `structured`、`bm25`、`vector`、命中词和最终分数，页面可以解释“为什么命中”，而不是只显示一个相似度。

当前后端名为 `HASHED_NGRAM_CONCEPT_VECTOR`。它是离线、确定性的特征向量，不是神经网络 Embedding，也不能对外宣称具备通用语义理解。后续接入专用 Embedding 时，只替换向量生成器，硬过滤、BM25、置信门槛和审计字段可以保持不变。

## 与旧检索的实测对照

冻结回归集包含 16 个手工标注案例：12 个应命中案例、4 个应拒绝的反例。

| 方法 | 总体正确率 | 正例 Top-1 | 反例拒绝率 |
|---|---:|---:|---:|
| 旧结构化规则 | 25.00% | 33.33% | 0.00% |
| 仅 BM25 | 93.75% | 91.67% | 100.00% |
| 仅特征向量 | 93.75% | 100.00% | 75.00% |
| 当前混合检索 | 100.00% | 100.00% | 100.00% |

BM25 在精确证据词上最稳；特征向量补到了 `serialisation/serialization` 一类变体，但单独使用时更容易误接纳反例；混合排序配合置信与歧义门槛，在这组回归数据上消除了两类问题。

运行命令：`python scripts/benchmark_skill_retrieval.py`。报告保存在 `artifacts/skill-retrieval/benchmark-report.json`。

这组数据是人工构造的离线回归集，不是生产流量，不能拿 100% 当线上准确率。下一步仍需冻结真实 Badcase，补 Recall@3、错误迁移率、Skill 命中后的工具调用变化和人工复核结果。
