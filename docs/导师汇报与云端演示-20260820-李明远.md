## 一、开场（约 40 秒）

大家好，我是李明远。这一轮我主要做了三件事：

1. 把 Mini-Drop 的控制面、Agent、Analyzer、Web 和测试目标部署到了云服务器；
2. 补齐 OTel 真实故障实验和统一测试集适配，让 CPU、内存、网络故障能够留下可复查的实验记录；
3. 把 AI 诊断继续收紧为“先采证、再归因”，模型给出的引用必须能对应到真实产物，否则系统会拦截结论。

我先演示一次真实任务，再看 AI 如何处理证据。

## 四、AI 诊断方案（约 3 分钟）

### 1. 打开 AI 诊断

左侧点击“AI 诊断”→“新对话”。输入：

> 订单服务最近 5 分钟 CPU 飙高，请定位原因。

### 2. 确认诊断范围

AI 会先询问服务、环境、Agent、PID 和时间窗口。这里填写当前测试目标后点击“确认并继续”。

我讲：

“我没有让模型直接猜 PID 或时间范围。范围不完整时，状态停在 `NEEDS_CLARIFICATION`。这个步骤解决的是诊断对象不清楚导致误采集的问题。”

### 3. 查看透明诊断流程

页面会展示六步：

1. 理解问题；
2. 确认范围；
3. 生成可证伪假设；
4. 通过性能决策树选择采集器；
5. 用真实产物支持或反驳假设；
6. 输出带证据引用、置信度和修复后复测要求的结论。

我讲：

“模型负责提假设和组织解释，策略层决定允许调用哪些工具。高风险操作要人工确认。最终报告由服务端质量门禁检查，不接受模型随便写一个路径来冒充证据。”

### 4. 展示本次真实模型调用结果

本次云端验收触发了诊断 `diag_20260820_105904_c3af57`。DeepSeek 确实被调用，但模型给出的三个 `evidence_refs` 不在实际证据路径中。系统重试两次后仍未通过，因此结果被标为 `MODEL_FAILED / INSUFFICIENT_EVIDENCE`，没有生成伪造根因。

我讲：

“这个结果本身不是一次成功归因，但它证明幻觉门禁在工作。现在的系统宁可明确说证据不足，也不会把不存在的字段包装成结论。要得到完整根因，需要再补一轮 perf TopN、eBPF 延迟或历史 baseline，然后重新推进诊断。”

### 5. 修复前后验证

当证据形成根因后，报告会给出修复建议。涉及变更的动作先由人确认。修复完成后，用相同 Agent、PID、采集器、时长和频率重新采样，对比修复前后的热点占比、P95/P99、CPU、RSS 或 I/O 延迟。

我讲：

“我把‘结论正确’和‘修复有效’分开处理。前者靠证据引用，后者靠同口径复测。这样诊断不会停在一句建议上。”

## 五、统一测试集与真实故障（约 1 分 30 秒）

打开“AI 诊断”→“方法与测试集”。

我讲：

“测试集不是打开页面就显示 100%。流程是先做安全预检和基线快照，再对白名单目标注入故障，确认指标变化，执行采集和诊断，最后与 Oracle 标准答案比较，并在 `finally` 中恢复目标。”

本轮补强内容：

- OTel CPU/内存/网络故障实验支持明确的服务地址和超时配置；
- 每次实验使用独立临时文件，避免并发写报告互相覆盖；
- 统一记录命令、返回码、stdout/stderr 摘要和时间戳；
- 外部测试案例可映射到 Mini-Drop 的证据契约；
- 已补充相关单测，本次变更涉及的 63 项测试全部通过。

页面上重点展示：

- 故障注入前基线；
- 故障期间快照；
- 恢复后快照；
- 诊断路径与工具调用；
- Oracle 根因；
- 证据覆盖率、结论命中率和恢复状态。

## 六、这轮修改的取舍（约 50 秒）

我认为目前最重要的不是再加一个聊天框，而是让每个结论都能回答三个问题：数据从哪里来、为什么能支持这个结论、修复后有没有变好。因此我保留了模型的推理能力，但把采集范围、工具调用、证据引用和最终结论都放进服务端约束里。

当前仍有一个真实边界：本次系统指标任务只能说明主机当时的负载情况，不能单独证明 CPU 热点根因。完整 CPU 归因要在原生 Linux 权限满足时补采 perf/eBPF，或者针对语言运行时采集 py-spy、async-profiler、pprof。这个限制会在页面和报告中明确显示。

## 九、现场故障时的处理

- 页面提示未认证：重新填写 Mini-Drop API Key 并点击“保存”；
- Agent 暂时离线：等待两个心跳周期后刷新，不重复创建任务；
- 模型返回证据不足：展示缺少的证据和建议补采项，不把它讲成完整根因；
- eBPF/perf 权限不足：切换到原生 Linux Worker，或者先演示系统指标、内存和语言级采集；
- 云端页面无法打开：用仓库中的截图和上述已验证任务 ID 说明链路，同时保留服务器健康检查结果。
