2. 在任务列表查找任务 **90**，进入“智能诊断”，对照诊断 **34（off）/35（experience）**；任务 **91** 对照 **36（off）/37（experience）**。这四次运行实际调用了 DeepSeek，启用经验的35/37分别加载案例1/2，方法版本和案例引用由Go附加，不能由模型自报。
3. 明确两组输入是 CPU线索、分配线索的**固定合成导入数据**。案例1/2也是受控合成种子；本次没有实时采集、复测或修复，不能把导入权重解释为真实 CPU时间、分配字节或业务延迟。`scripts/evaluation/` 的固定评测用于检查路由与报告协议边界，不等于模型准确率。
4. 展示一个已知错误：诊断 **37** 将排名1称为“唯一叶帧”，实际有 **70%/30%两个正权重叶帧**；诊断35把60秒/99Hz归因于E7，但E7只要求人工导入可比对照，没有返回这些参数。34/36的草案出处也有歧义，应区分模型建议、工具返回和已经验收的计划。
5. 说明案例 **3** 复用的是既有 Saber **调查11→任务86→诊断29→修复9** 的成功回执。入库证明历史结果可追溯、可作为先验；本轮没有重新运行该修复基准，也不代表当前任务根因已验证。

[实际调用对照](evidence/diagnostic-knowledge-20261021/evaluation-live.json)记录两组 off/experience 的真实报告与用量。[语义复审](evidence/diagnostic-knowledge-20261021/agent-review.json)由 Codex Agent 只读核对，类型为 `agent_review`、`human_manual_review=false`，不是独立人工标注或准确率。根因类别命中率、必要拒答召回率、正常负载误报率等语义指标均保持 `NULL`；两组可见合成样例不能证明经验提升准确率。面试中应主动说明：工具调用和引用校验能收住程序边界，解释语义仍需复核。

## 页面操作

1. 进入“智能性能调查”，点击“选择已接入的 Python CRM”。这里把节点与实时进程身份绑定起来，而不是让模型猜PID。
2. 输入下面的问题，勾选采集/自动分析授权，以及源码片段和隔离修改授权，点击“生成采集计划”。

   > 定位Python CRM品牌配色预览的CPU热点。选择Python调用栈采集10秒99Hz并关闭native扩展、聚焦Python函数，自动复测核对，再定位绑定源码，生成保持Python返回类型和可变对象隔离的最小优化补丁，执行原功能回归与多组CPU对照。

3. 展开计划工具观测，说明模型从节点实际支持的采集器及参数schema中选择方案。核对时长/频率，再点“确认计划并执行闭环”。
4. 随着页面更新，展示采集、诊断、自动复测与再次诊断。等待时解释C++采集、Go状态机、Python解析和React展示的分工，以及attempt/租约/授权校验。
5. 查看两次证据比较。样本占比不等于业务延迟，重复采样不确认因果；样本不足时页面会保留证据不足的结论。
6. 点击“查看补丁及实际验证”，依次展开真实profile、源码SHA/行号、实际补丁、原功能回归和交替A/B结果。以现场实际结果为准，不预报固定加速比。

每次新源码修复都会重新执行测量；同一修复内的重复工具或故障恢复可以复用本次已完成的结果。工具观测中的`cache_hit=false`表示这次执行了沙箱测量，`true`表示明确复用了当前修复的结果。模型不能自选其他修复ID。新调查不会直接套用历史修复#4的测量数据。

报告格式校验失败时，最多额外一次不含工具的格式纠错请求，仍使用相同引用/字段/长度校验和150秒总预算；继续不合法则明确失败。普通数学比较符号可作为纯文本显示，HTML标记仍拒绝，页面始终以转义文本渲染。

## 面试讲解重点

- **为何是Agent**：模型选择工具，工具执行结果和参数错误再作为观测回填，允许在预算内调整；不是固定顺序调用模型生成一段报告。展示行动和证据，不展示隐藏思维链。
- **如何判断AI输出**：证据引用必须真实存在，行号必须来自固定版本的真实profile；补丁要通过原测试、Python类型/可变对象隔离、接口身份/限流、384次严格输出比较及6组交替CPU对照。
- **一次有价值的失败**：旧模型补丁把list改成tuple，JSON等价比较漏掉类型变化。人工复核后撤销采纳，补上严格类型检查；错误补丁实际重跑被拒绝。这是质量保障工作，不应隐去失败记录。
- **边界**：当前源码preset覆盖配色业务函数，修复在无网络隔离副本执行；没有直接发布原CRM，也不能把基准结果写成全CRM或生产P95收益。模型解释仍需要人工判断。

历史调查#4与源码修复#4是已完成的结果，可用于讲解和故障备用，但应明确是历史记录。面试前检查入口和节点在线，再新建一条现场任务。若现场外部模型调用失败，展示实际失败状态和保留的工具证据，不把历史结果冒充实时结果。
