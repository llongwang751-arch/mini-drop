# Mini-Drop 基础与亮点测试集执行报告

## 1. 结论先行

本轮测试拆成两部分：

1. 基础测试集：`运维Agent多赛道评测最终交付-20260822(1).zip`
2. 项目亮点测试集：诊断策略自进化测试，包括 15 个独立用例和 11 步连续对抗 Campaign

亮点测试已经实际执行：

| 测试 | 基线 | 启用策略自进化 | 结果 |
|---|---:|---:|---|
| 15 个独立用例 | 6/15 | 15/15 | 通过 |
| 11 步连续对抗 Campaign | 不适用 | 11/11 | 通过 |

基础测试集曾执行 9 个用例、每例 3 次，共 27 次。但该轮所有请求都因模型接口返回 HTTP 401 而进入规则降级，未真正调用模型。因此旧分数已标记为 `INVALID_PROVIDER_CONFIGURATION`，不能用于能力排名。

## 2. 基础测试集为什么分低

旧报告中的低分不是一个单一问题：

1. 模型接口鉴权失败。27 次输出都是规则降级文本，模型调用数为 0。
2. 适配器曾丢失公开用例原有的 `evidence_ref`，使证据覆盖率被错误计为 0。
3. 旧运行脚本没有启动前预检，导致配置失败后仍完整运行 27 次并生成了看似正式的分数。

本轮已完成以下修复：

- 运行 27 次之前先调用一次模型接口；接口不可用时立即停止。
- 默认禁止把规则降级结果当成 AI 正式成绩。
- 导入公开用例的 `tool_results` 和稳定 `evidence_ref`，并让引用校验器识别这些编号。
- 评分报告增加 `run_validity`，把配置失败与能力失败分开。

当前预检结果是 HTTP 401。需要配置一个有效的 OpenAI-compatible 模型接口后重新运行，才能得到新的基础集有效分数。不能根据私有 Oracle 直接修改答案，也不能把规则写死到 case ID 上。

为确认基础测试的非模型链路，本轮仍使用 `--allow-rule-fallback` 完成了 27 次回放。评分器将该轮明确标记为 `INVALID_PROVIDER_CONFIGURATION`；报告中的 0.2222 等数值只用于定位适配和兜底链路，禁止作为模型成绩或跨项目排名依据。

## 3. 亮点测试为什么更难

原有 15 个用例彼此独立，主要验证：相似事故复用、误导样本拒绝、环境漂移、错误反馈隔离、版本回滚和污染证据拒绝。

新增 11 步连续对抗 Campaign 后，后一步依赖前一步真实写入数据库的状态：

1. 从已验证诊断沉淀策略 v1。
2. 相似事故复用已验证采集路径。
3. 面对“症状相似、机制不同”的网络事故拒绝错误迁移。
4. perf 权限或能力漂移时回退到基础路径。
5. 一次错误反馈不能立即误杀有效策略。
6. 重复负迁移后自动隔离 v1。
7. 从新的已验证轨迹发布 v2。
8. 发布 v3，并保留版本历史。
9. v3 失败后回滚到 v2。
10. 回滚后下一次相似事故仍能正常复用 v2。
11. 证据来源断裂时拒绝污染策略进入技能库。

这类测试不能靠每次输出同一段“标准诊断”通过，必须具备跨轮状态、证据门禁、负迁移控制和版本生命周期。

## 4. 如何复现

在项目根目录 `D:\tx\mini-drop` 的 PowerShell 中执行：

```powershell
python -m pytest -q tests/test_diagnostic_skill_benchmark.py tests/test_diagnostic_skill_evolution.py tests/test_rca.py
python scripts/run_skill_evolution_benchmark.py
```

亮点报告位于：

```text
artifacts/skill-evolution/benchmark-report.json
```

本轮核心亮点评测回归为 `15 passed`；项目更宽范围的历史回归结果不能替代本次测试。亮点交付包已升级为与基础集相同思路的盲测交付结构：

```text
artifacts/deliverables/Mini-Drop策略自进化亮点测试集-20260825-v5.zip
artifacts/deliverables/Mini-Drop策略自进化亮点测试集-20260825-v5-盲测公开包.zip
```

`v5` 增加公开题面/私有 Oracle 分离、干预事件、统一 Agent 契约、来源锁、冻结哈希、独立评分器和交付校验。完整包复核为 `DELIVERY_OK cases=15 hashes=7`，盲测公开包为 `DELIVERY_OK cases=15 hashes=6`，公开包未发现私有答案或参考结果泄漏。

配置有效模型后，再运行基础集：

```powershell
python scripts/run_multitrack_delivery.py ".tmp-base-benchmark-readonly\运维Agent多赛道评测最终交付-20260822\运维Agent多赛道评测统一交付-20260822"
python scripts/score_multitrack_delivery.py ".tmp-base-benchmark-readonly\运维Agent多赛道评测最终交付-20260822\运维Agent多赛道评测统一交付-20260822"
```

## 5. 与其他组员公平对比的条件

要证明某个方案更好，三套系统必须满足：

- 使用相同公开输入和私有 Oracle。
- 使用相同模型、温度、重试次数和时间限制。
- 每个用例重复相同次数。
- 不允许把 case ID、私有 Oracle 或期望根因传给模型。
- 统一统计根因 Top1、机制匹配、证据覆盖、拒答校准、干预后修正、负迁移、回滚恢复。

在其他成员项目尚未接入同一适配器前，本报告只证明 Mini-Drop 当前实现通过了自己的状态化安全门禁，不能提前宣称已经击败其他项目。
