## 3. 评测中发现并修复的真实问题

首轮 90 次执行中，连续回放内存故障时出现 7 次失败。排查发现原因不是 AI 逻辑，而是 Python 进程释放对象后，glibc 分配器仍保留 RSS 高水位，导致下一次回放的基线过高。

修复方式：

1. 停止内存故障时先执行 `gc.collect()`；
2. Linux/glibc 环境下尽力调用 `malloc_trim(0)` 将空闲堆页归还操作系统；
3. 增加独立回归测试；
4. 部署后只断点重跑失败的 7 条，不覆盖原有 83 条成功证据；
5. 最终 7/7 补测通过，合并为完整 90/90 结果。

对应提交：`7a4c06e 评测：释放内存故障堆以稳定连续回放`。
