# 资源自适应反事实根因验证验收指南

## 1. 这项功能解决什么问题

普通性能诊断常常只能发现“两个现象同时出现”。资源自适应反事实验证进一步追问：如果只改变疑似原因，异常是否随之消失？默认使用一台机器分时验证；资源足够时，再增加独立对照节点排除同时发生的环境变化。

这项能力是李明远方案的独立亮点。它不替代原来的 AI 诊断，也不复制其他同学的上下文删除或源码行定位。

## 2. 人工干预到底保留什么

保留：

1. 人工核对实验组、对照组、PID、唯一干预和清理动作；
2. 人工批准或拒绝 R2 实验；
3. 人工调整采样时长和目标；
4. 人工评价结论并反馈错误。

不做：

1. 人工删除历史诊断上下文；
2. 删除不利证据后重新生成结论；
3. AI 绕过审批执行生产变更；
4. AI 自由执行任意 Shell。

## 3. 页面验收步骤

### 3.1 准备诊断与假设

1. 打开 `AI 诊断` 页面，新建一个诊断会话；
2. 填写服务、环境、Agent、PID 和时间范围；
3. 推进诊断，直到页面生成至少一个待验证假设；
4. 滚动到 `资源自适应反事实根因验证` 卡片。

验收点：卡片顶部必须明确显示“这不是删除上下文，也不是让 AI 自己改生产环境”。

### 3.2 创建待审批实验

1. 选择一个待验证假设；
2. 选择当前可用模板：CPU 热点、内存持续增长或下游延迟；
3. 默认选择 `单机交替验证（推荐，省资源）`，只填写一个 Agent/PID；
4. 如果确有两台配置和负载接近的节点，可选择 `双节点并行对照`，此时两组 Agent 必须不同；
5. 点击 `生成待审批实验方案`。

预期结果：状态是 `等待人工审批`，页面展示待验证假设、唯一干预变量、对照组约束、主指标和清理动作。此时不能录入裁决结果。

### 3.3 验证人工审批

批准路径：点击 `核对无误并批准`。状态变为 `已批准，等待证据`。

拒绝路径：点击 `拒绝实验`。状态变为 `已拒绝`，不进入四窗口取证。

审计验收：在诊断事件中应看到 `causal_experiment.planned` 与 `causal_experiment.decision`。批准或拒绝都保留，不删除旧上下文。

### 3.4 录入四窗口证据

批准后展开 `录入已完成采集任务的四窗口证据`，依次填写：

| 窗口 | 含义 | 示例 P99（处理/对照） |
|---|---|---|
| 正常基线 | 没有故障时 | 100 / 100 |
| 故障窗口 | 异常已经出现 | 180 / 175 |
| 单变量干预 | 只处理实验节点 | 105 / 170 |
| 清理恢复 | 撤销干预并确认安全 | 102 / 101 |

每个窗口还必须填写已完成采集任务 ID 或证据引用。点击 `根据透明门槛计算结论`。

预期结果：

- 单机模式中故障明显、干预有效且恢复接近基线时，返回 `单机交替实验支持该假设`，置信度最高 75%；
- 双机模式中处理组明显改善、对照组没有同步改善、恢复接近基线时，返回 `因果关系已证实`；
- 干预没有带来改善时，返回 `当前假设已被推翻`；
- 效应不稳定时，返回 `效应不明确`；
- 缺少对照值或证据来源时，返回 `证据不足`。

页面必须展示置信度、裁决理由和差中之差，不由大模型自由编写裁决。

## 4. 接口验收

主要接口：

```text
GET  /api/v2/causal-replay/cases
POST /api/v2/diagnoses/{diagnosis_id}/causal-experiments/preview
POST /api/v2/diagnoses/{diagnosis_id}/causal-experiments
GET  /api/v2/diagnoses/{diagnosis_id}/causal-experiments
POST /api/v2/diagnoses/{diagnosis_id}/causal-experiments/{experiment_id}/decision
POST /api/v2/diagnoses/{diagnosis_id}/causal-experiments/{experiment_id}/evaluate
```

## 6. 当前不能夸大的部分

当前版本完成了“实验计划、人工审批、四窗口证据、透明裁决、审计留痕”的闭环。默认单机交叉模式适配当前 `2 核 4GB` Worker；双机模式只在两个 Worker 空闲时启用。Campaign 自动执行实验、自动读取任务产物和自动验证清理尚未接通，因此演示时应称为“可运行的资源自适应反事实验证 MVP”，不能称为全自动生产级因果实验平台。
