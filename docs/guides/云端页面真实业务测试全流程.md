# Mini-Drop 云端页面真实业务测试全流程

> 目标：在已按可信发布流程部署且入口已验证的前提下，验收人员只使用浏览器完成真实开源缺陷的机制复现与 AI 诊断验证。电脑端无需安装或操作 Docker，也无需在终端执行测试命令。本文不构成云端验收已完成的证明。

## 1. 先说明测试到底在哪里运行

- 浏览器只是操作入口。
- 测试由云端 Mini-Drop Server 创建并执行。
- 页面轮询云端 run 状态，展示真实时间线、快照和诊断结果。
- 公开题面与私有 Oracle 分开；Oracle 在诊断完成后才参与评分。
- 云端运维底层目前使用容器承载服务，但验收者不接触 Docker。

这不是“AI 沙箱测试”。判断依据是每次运行都有独立 run ID、服务端时间戳、阶段状态、baseline/incident/verification 三段数据和最终 Oracle 对照。

## 2. 打开页面

1. 浏览器访问已通过可信 TLS 证书和主机身份验证的 Mini-Drop 云端入口。
2. 在右上角填写 **Mini-Drop API Key**，点击“保存”。这里填写的是平台访问密钥，不是大模型密钥。
3. 点击左侧“AI 诊断”。
4. 点击左栏页签“方法与测试集”。
5. 在右侧主区域找到“真实开源缺陷：页面化云端复现与成熟产品对照”。

## 3. 页面每一块是什么意思

### 3.1 数据集概览

- “候选案例 7”：已经核验来源、题面和私有答案的案例数。
- “页面适配器 4”：已有页面执行适配器的机制级复现数；只有产生服务端 run 证据的部署执行才可计为云端运行。
- “完整上游复现 0”：尚未拉取并编译全部原始项目的 base/fix 版本。
- “成熟产品实测 0”：尚未在完全相同输入、模型和预算下运行对照产品。

这四个数字故意分开，防止用“有题面”冒充“已跑通”。

### 3.2 案例目录

每行包含：案例 ID、真实项目、故障机制、上游 PR、复现级别和操作按钮。

- 绿色“在云端运行”：可以直接执行。
- 灰色“尚无执行适配器”：只有题面，当前不计入运行通过率。
- “MECHANISM_REPRO”：复现核心故障机制，不代表完整上游项目 A/B。

### 3.3 运行过程

在已部署的云端入口点击按钮后，依次出现：

1. PREFLIGHT：确认案例允许执行、资源满足要求；
2. BASELINE：记录正常状态；
3. INCIDENT：启用白名单故障机制并记录异常；
4. DIAGNOSIS：根据可见证据给出根因；
5. VERIFICATION：关闭故障并确认指标恢复；
6. ORACLE_COMPARISON：诊断结束后才读取标准答案；
7. COMPLETED：生成评分、证据引用与局限说明。

## 4. 四个案例怎么验收

### 4.1 Grafana 队列去重失效

点击 `RW-GRAFANA-123359` 的“在云端运行”。

应看到：

- baseline：600 个事件被 10 个稳定键去重；
- incident：使用对象身份作为键，队列增长到 600；
- verification：恢复稳定键后重新回到 10；
- 诊断：页面仅显示非敏感的评分状态和证据引用；隐藏答案字段不展示。

这验证系统能从“队列增长/对象保留”定位到键设计，而不是只说“内存泄漏”。

### 4.2 OpenTelemetry Python 强引用保留

点击 `RW-OTELPY-4224` 的“在云端运行”。

应看到：

- baseline：弱引用路径结束后存活对象为 0；
- incident：强引用 bound method 保留 600 个对象；
- verification：改回 WeakMethod 后存活对象回到 0；
- 诊断：页面仅显示非敏感的评分状态和证据引用；隐藏答案字段不展示。

### 4.3 Kubernetes 周期性 full sync

点击 `RW-K8S-138571` 的“在云端运行”。

应看到：

- baseline：事件驱动路径约 150 次 dataplane 操作；
- incident：大集群 full sync 放大到约 9000 次；
- verification：关闭周期性全量同步后回到约 150；
- 诊断：页面仅显示非敏感的评分状态和证据引用；隐藏答案字段不展示。

### 4.4 Envoy debug 表达式逐块求值

点击 `RW-ENVOY-42752` 的“在云端运行”。

应看到：

- baseline：关闭 debug 时求值次数为 0；
- incident：4000 个 chunk 导致 4000 次无效求值；
- verification：增加日志级别 guard 后回到 0；
- 诊断：页面仅显示非敏感的评分状态和证据引用；隐藏答案字段不展示。

## 5. 如何判定通过

单个案例需同时满足：

- run 状态为 `COMPLETED`；
- 七个阶段均有服务端时间线；
- baseline、incident、verification 三段快照齐全；
- incident 与 baseline 存在预期差异；
- verification 恢复到正常范围；
- 诊断引用至少一条证据；
- Oracle 对照发生在诊断之后；
- 页面明确显示复现级别与局限。

## 6. 成熟产品对照怎么看

页面列出 RCAEval、OpenRCA、HolmesGPT 和 Grafana Pyroscope，目的是说明比较维度：

- RCAEval：服务/指标根因 Top-K；
- OpenRCA：LLM 工具选择和遥测推理；
- HolmesGPT：多轮 SRE 调查；
- Pyroscope：持续 Profiling 与火焰图体验。

当前没有同预算实测结果，所以页面不显示虚构分数。后续只有在相同事故窗口、相同遥测、相同模型和工具预算下跑完，才填写对比结果。

### 6.1 页面上的真实对照步骤

1. 先选择一个已有执行适配器的真实缺陷案例，点击“在云端运行”。
2. 等 run 进入 `COMPLETED`，确认页面具有独立 run ID、三段快照和证据引用。
3. 点击“下载同条件对照输入”。下载包只有公开题面、冻结遥测、统一模型/工具/时间预算和输出契约，**没有 Mini-Drop 的结论，也没有隐藏 Oracle**。
4. 按产品能力选择对照赛道，而不是把不同产品硬算成同一种能力：
   - `offline_service_rca`：RCAEval；
   - `offline_llm_tool_rca`：OpenRCA；
   - `live_agent_investigation`：HolmesGPT；
   - `continuous_profiling_experience`：Grafana Pyroscope。
5. 将同一输入交给产品运行，要求使用相同模型、最多 12 次工具调用和 300 秒超时；记录产品真实输出、耗时和工具轨迹。
6. 在读取 Oracle 前冻结产品输出。点击“下载统一结果模板”，把导出包中的 `source_run.run_id` 填入 `source_run_id`，把 `input_hash` 原样填入 `comparison_input_hash`；不得填入 `oracle`、`ground_truth`、`golden_answer` 等标准答案字段。
7. 在对应产品行点击“导入实测 JSON”，粘贴并提交。服务端会校验产品身份、案例、输入哈希、源 run、工具/时间预算和 Oracle 泄漏，并以服务端登记的三阶段遥测替换产品自带证据副本，然后保存结果哈希。
8. 只有服务端隐藏评测器就绪时，页面才显示证据优先得分、Top1、源码定位率、证据引用率和三阶段快照率。评测器未配置时只显示“已冻结、等待评分”，不会伪造分数。

### 6.2 为什么要分赛道

RCAEval/OpenRCA 主要测离线根因定位，HolmesGPT 主要测在线调查，Pyroscope 主要测持续 Profiling。某产品不具备 AI 归因或进程采集能力时，页面应标为“不等价能力”，而不是把“不支持”算成错误诊断。最终汇报应分别给出各赛道结果，再说明 Mini-Drop 的差异点：把真实进程采集、循证诊断、人工审批、隐藏 Oracle 评测和恢复验证放在一条可审计链路中。

| Grafana Pyroscope 2.2.1 | 官方镜像已摄取同一 CPU 热点 workload，并查询到 `order_compute` | “持续 Profiling 能力对照已跑通”，不称为 AI 根因对照 |
| HolmesGPT 0.39.0 | 安装和同输入调用已执行，模型供应商返回 HTTP 401 | “执行被外部鉴权阻塞”，不展示虚构诊断或分数 |
| OpenRCA / RCAEval | 当前 2C/3.4GB 云机低于官方建议资源 | “当前环境不支持”，等待专用评测机 |

点击页面中的证据链接时，应能对应到仓库 `reports/benchmark/` 下的原始报告。若页面只有分数而没有 `source_run_id`、输入哈希或证据路径，该结果不算完成。

当前代码实现了 4 个真实 PR 对应机制的页面执行适配器；本阶段尚未重新部署或取得三节点云端验收证据。这些适配器也不是 4 个大型开源仓库的完整编译、部署和 base/fix A/B。完整上游复现需要独立 runner、固定 commit、依赖缓存和更高资源配额，完成后才能把 `execution_fidelity` 升级为 `FULL_UPSTREAM_REPLAY`。

## 8. 出现异常时怎么判断

- 页面提示 401/认证失败：重新填写 Mini-Drop API Key 并保存。
- 案例按钮灰色：该案例尚无执行适配器，不属于故障。
- 状态长时间不更新：点击页面刷新，并查看是否仍有 run ID 和时间线增长。
- 状态 FAILED：记录 run ID、失败阶段和错误文本；该次不得计入通过。
