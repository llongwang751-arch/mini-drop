# AGI-saber 与 Mini-Drop 面试问答

> 口径日期：2026-09-07。回答以当前本地源码、测试和验收材料为准。简历中的旧数字会单独说明，不能与当前版本混为一次实验。

## 一、AGI-saber

### 1. 请介绍一下 AGI-saber。

AGI-saber 是一个基于 Python、FastAPI 和 Vue 的个人办公 Agent，主要解决资料分散、私有知识检索困难，以及大模型回答缺少可靠引用的问题。

文档上传后，系统会完成解析、清洗、父子分块和索引构建；用户提问后，会进行查询改写、向量和 BM25 混合召回、RRF 融合、Rerank、父块回填、去重和无答案判断，最后生成带引用的回答。知识库问答之外的请求进入统一工具执行链，由 Planner 生成任务和依赖，TaskGraph 校验图结构，GraphRuntime 负责拓扑并行、超时、重试、取消、快照和有限重规划。

我重点负责 Python/FastAPI 后端、RAG 质量链路、Agent Runtime 和评测能力的实现与验证。

### 2. 这个项目解决了什么问题？

它主要解决三个问题：第一，个人资料散落在 PDF、Markdown 等文件里，普通关键词检索不容易找到同义表达；第二，大模型脱离私有资料时容易生成泛化或没有出处的回答；第三，复杂办公请求可能涉及多个工具和步骤，需要处理失败、取消、恢复和过程追踪，不能只依靠一次模型调用。

### 3. 一份 PDF 上传后，怎样变成可检索的知识？

后端先尝试从 PDF 中提取文本，目前会依次尝试 pdfplumber、PyPDF2 和 pdftotext。无法提取有效文字时，会提示需要 OCR，但项目当前不直接执行 OCR。

提取后进行文本规范化，主要处理换行、空字符、跨行连字符、多余空白和空行。然后保存文档及版本信息，再做父子分块：先切父块，再在父块内部切子块。对子块生成向量并建立检索索引，父块保留完整上下文，供命中子块后回填。

### 4. 项目有没有智能删除 PDF 页眉和页脚？

当前没有完整实现智能页眉页脚识别。现有清洗主要处理换行、空字符、跨行连字符和多余空白。面试中不能把“普通文本化”说成“已经准确删除所有页眉页脚”。

### 5. 为什么要分成父块和子块？

子块负责检索精度。块太大会包含多个主题，导致语义信号被稀释；父块负责上下文完整性，避免模型只看到一句残缺内容。查询时先用子块精确召回，再找到对应父块补足上下文。

### 6. 当前父子块大小是多少？为什么这么设置？

当前默认子块大小是 200 字符，重叠 50 字符；父块通常是 800 字符，重叠 100 字符。这里的单位是字符，不是 Token。

这是经验默认值：子块太大影响召回精度，太小容易丢失语义；父块太大引入噪声，太小又无法补全上下文。当前还没有足够的消融实验能够证明这组参数最优。

### 7. 为什么分块之间需要重叠？

重叠太小，可能把一句话、一个条件或实体关系切断，导致关键证据无法被完整召回；重叠太大，会造成索引膨胀、候选高度重复，增加 Rerank 和生成成本。适度重叠是在语义连续性和检索成本之间折中。

### 8. 用户提问后，RAG 完整链路是什么？

用户提问后，系统先按需改写查询，默认可生成三个查询；然后同时进行 Milvus 向量召回、Elasticsearch BM25 关键词召回，以及可选的 Neo4j 图检索。

多路结果先通过 RRF 融合。如果有多个改写查询，会进行两级 RRF。融合后的候选再交给远程 Rerank 重新判断相关性，随后根据命中的子块回填父块并去重。只有远程 Rerank 成功并产生有效的零到一相关性分数时，才使用无答案阈值。最后将父块上下文和原问题交给大模型，生成带结构化引用的答案。

### 9. 为什么要混合检索，不能只用向量检索？

向量检索擅长同义表达和语义相似，但对专有名词、编号、产品型号和精确关键词不一定稳定。BM25 可以补足精确词匹配，图谱可以补足实体关系和多跳路径。混合检索的目标是让几种召回方式互相补足，而不是假设某一种检索能覆盖所有问题。

### 10. 为什么不用多路原始分数直接相加？

向量相似度、BM25 分数和图检索分数的量纲、范围和分布不同，直接相加需要复杂校准。RRF 只依赖每一路的排名，用排名倒数进行融合，对不同检索系统的分数尺度更稳健。

### 11. RRF 和 Rerank 有什么区别？

RRF 负责融合不同召回通道的排名；Rerank 负责细读用户问题和候选段落，重新判断相关性。Rerank 不是再次融合三路检索，而是在 RRF 得到的候选集合上做更精细的排序。

### 12. 当前 RAG 权重和阈值是多少？

当前语义和关键词权重是 0.65 和 0.35，启用图谱时图检索有单独的 0.3 权重。无答案阈值是 0.30，父块近重复去重阈值是 0.85。

这些值是当前配置，不代表已经通过真实业务数据证明最优。0.85 是字符三元组和编辑相似度阈值，不是向量余弦阈值。

### 13. 为什么无答案判断放在 Rerank 后？

RRF 分数是排名函数，不具备统一的相关概率语义，不能直接和 0.30 比较。当前只有远程 Rerank 成功后输出的零到一相关性分数，才会进入无答案门禁。降级后的本地分数没有完成同样的校准，因此不能直接复用同一阈值。

### 14. 引用和 Trace 分别解决什么问题？

引用面向用户，告诉用户答案依据哪份文档、哪个父块和哪个版本，方便核对原文，是用户的信任锚点。

Trace 面向研发和测试，记录查询是否改写、各路召回结果、RRF 顺序、Rerank 变化、父块回填、无答案判断、工具调用和错误。出现问题时，可以判断是召回失败、融合排错、重排误杀，还是生成没有正确使用证据。

### 15. 项目使用了哪些模型和外部 API？

聊天生成使用火山方舟的 OpenAI 兼容接口，当前模型是 DeepSeek V4 Flash。配置中的 fast model 为空，因此查询改写、规划和远程 Rerank 当前仍然复用同一个 DeepSeek 模型。

Embedding 使用火山方舟的豆包多模态向量模型，输出 2048 维向量。当前 RAG 实际只向它传入文本，没有实现图片入库检索。联网搜索可以选用 Tavily，但不是普通 RAG 的必需依赖。

项目没有单独的 Rerank API。远程 Rerank 复用 DeepSeek，本地降级使用确定性的关键词重合算法；Cross-Encoder 只预留了配置，当前没有实际模型。

### 16. Embedding 使用 BGE-M3 吗？

没有。当前使用豆包多模态 Embedding。BGE-M3 可以作为专用文本向量模型或本地化部署候选，但需要在相同评测集上比较 Recall@K、延迟、成本和部署复杂度，不能直接认为换成 BGE 就一定更好。

### 17. 为什么生成模型不能直接代替 Embedding 模型？

生成模型的训练目标主要是预测下一个 Token，输出自然语言；Embedding 模型的目标是把文本编码成稳定的固定维度向量，让语义接近的文本在向量空间中更靠近。两者的训练目标、输出形式和使用接口不同。

### 18. 熔断器的关闭、打开和半开分别是什么？

关闭态表示正常调用远程服务。连续三次失败后进入打开态，后续请求直接走本地降级，不继续等待远程超时。三十秒后进入半开态，只允许一个探测请求；成功则回到关闭态，失败则再次打开。

熔断的目的不是提高重排质量，而是在远程服务故障时防止延迟扩散，保证系统仍然可用。

### 19. 当前系统怎样路由请求？

当前顶层主线已经收敛为两类：知识库已启用且有内容时走只读 RAG；其他请求进入统一工具执行链。统一执行链内部再根据工具和任务复杂度决定直接调用工具，还是使用 ReAct 式多步执行。

专用报告工作流已经移除。系统仍可以生成报告文本，也保留文档能力，但不会自动进入固定的 Research、Writer、Review、Doc 流程。

### 20. Router、Planner、TaskGraph 和 GraphRuntime 分别负责什么？

Router 负责选择请求路线。Planner 负责生成任务节点、参数和依赖。TaskGraph 负责保存图、校验缺失依赖和循环依赖，并记录节点状态。GraphRuntime 负责按拓扑层调度任务，同一层可以并行，同时处理竞速、超时、重试、取消、快照和有限重规划。

### 21. 为什么使用任务图，而不是线性步骤？

任务图可以明确表达依赖关系，让互不依赖的任务并行执行，并把失败范围限制在具体节点。比如同时查询北京和上海天气，再生成出行对比，两次天气查询可以并行，汇总节点等待两者完成。如果一个查询失败，只需要重试对应节点；恢复时也可以从已经完成的节点继续，而不是整条链从头执行。

### 22. 为什么没有直接使用 LangGraph？

AGI-saber 当前主要解决无环工具任务的依赖调度，需求集中在依赖校验、拓扑并行、重试、取消和快照，因此先实现了更轻量的 TaskGraph 和 GraphRuntime，也更容易接入现有后端状态和审计。

这不代表自研方案比 LangGraph 更强。它的代价是通用持久化、复杂循环、人工中断和分布式调度能力需要自己维护。如果后续循环决策和人工审批越来越复杂，应重新评估 LangGraph。

### 23. Retry 和 Replan 有什么区别？

Retry 表示计划没有问题，只是某个节点发生了临时执行失败，例如网络超时或接口限流，输入和目标不变，重新执行同一个节点可能成功。

Replan 表示原计划或路线本身不再合适，需要基于已经完成的结果修改后续节点、增加步骤或更换工具，不是把所有已完成工作全部清空。

判断标准是：同样操作再做一次可能成功，就 Retry；同样操作再做一次也没有意义，就 Replan。

### 24. 当前动态重规划是否开启？

GraphRuntime 的代码默认值是关闭，但当前仓库的 config.yaml 将它开启，最多重规划两次，并允许在节点失败时触发。面试时要区分“代码默认值”和“当前运行配置”，不能简单说它一直关闭。

### 25. 短期记忆怎样实现？

短期记忆当前保留最近五轮原始对话，超过窗口后移除更早消息。系统提示词是每次请求时另外组装的。AGI-saber 当前没有实现“把中间历史摘要后永久保留”的短期记忆方案，这只能作为后续优化方向。

### 26. 长期记忆是不是直接存进 Milvus？

不是。系统先从对话中提炼值得长期保存的事实或偏好，然后保存文本、向量、重要度和类别，运行时根据当前问题的相关性召回。当前长期记忆可持久化到 PostgreSQL 或本地 SQLite，并支持去重、合并、衰减和淘汰。Milvus主要用于文档向量检索，不能把两者混为一谈。

### 27. 工具调用有哪些安全边界？

模型只能从已注册工具中选择，不存在的工具会在执行前被拒绝。命令工具只在沙箱启用时注册，容器可以禁网、使用只读根文件系统、移除权限，并限制 CPU、内存、进程数、执行时间和输出大小。

当前危险命令识别仍主要依赖规则，不是完整 Shell 语法分析，部分参数也没有统一强校验。因此应该说项目采用纵深防御，而不是绝对安全。

### 28. 怎样评测 RAG 效果？

先建立包含问题、标准答案、标准证据和无答案标签的评测集，再分层评测。

入库层看解析完整性、分块质量和父子映射；检索层看 Recall@K、MRR、nDCG 和 Evidence F1；生成层看答案正确性、忠实度、引用支撑和无答案拒答；工程层看 P50/P95、错误率、降级率、Token 和 API 成本。

要证明某个组件有效，应在同一批问题上做消融实验，例如比较纯向量、向量加 BM25、再加 Rerank，而不是只看几条演示问答。

### 29. 当前评测集做到了什么程度？

当前有十二条合成脱敏演示用例，覆盖意图、必填信息、工具选择、参数、RAG 证据、异常兜底、安全和 Trace，并实现十项确定性指标。

Replay 中 baseline 0/12、fixed 12/12 是人为构造的固定输出，只证明评测平台能够识别问题并验证修复，不代表真实模型准确率从 0% 提升到 100%。真实业务标注集规模仍然不足。

### 30. AGI-saber 当前测试和简历数字为什么不同？

简历记录的是投递时的历史快照：47 个路由、4 段迁移、122 passed 和 4 skipped，以及当时的接口冒烟和压测数据。

当前本地仓库已经演进为 79 个显式业务路由、10 个 Alembic 迁移，本次全量回归实跑结果是 274 passed。面试时应明确说明版本时间，不能把旧压测、当前测试和 RAG 质量指标拼成同一组结果。

### 31. AGI-saber 最困难的工程问题是什么？

RAG 侧最困难的是让多依赖链路在部分服务失败时仍然可用并且容易定位：权威数据和检索投影要分开，索引可以重建，远程服务要有熔断和降级，每个阶段要有 Trace。

Agent Runtime 侧最困难的是处理有副作用任务的一致性：并行、重试、取消和恢复时，不能重复生成文件或重复调用工具，还要保留已经完成节点和失败原因。

### 32. 当前还有哪些没有真正验证？

还缺少足够大的真实业务标注集；父子块大小、RRF 权重、图检索增益、Rerank 策略和 0.30 阈值没有完成充分消融；多模态 Embedding 当前只使用文本；本地 overlap 重排不等价于正式 Cross-Encoder；当前单机 GraphRuntime 也不能称为成熟分布式调度平台。

## 二、Mini-Drop

### 33. 请介绍一下 Mini-Drop。

Mini-Drop 是面向开发和 SRE 的 Linux 多节点性能诊断平台，解决传统排障需要手工登录机器、拼接命令、跨节点收集数据，而且结论依赖个人经验、难以复现和审计的问题。

用户描述故障后，系统会发现在线 Agent 和新鲜进程，签发绑定 Agent、PID、启动时间和命名空间的不透明目标。Diagnosis Worker 结合 Knowledge RAG 和 Skill 生成多个可证伪假设，LATS 在预算内选择下一条调查分支。服务端通过工具白名单、运行时能力、权限、预算和审批门禁后创建真实采集任务。C++ Agent 执行采集，Python Analyzer 生成火焰图、TopN 或调用图，再由 Evidence Gate 决定证据是否支持或反驳假设。最终报告必须引用本次诊断中新采集的 Evidence。

我重点负责 AI 诊断主链，包括方案调研、假设搜索和推理编排、证据约束，以及全链路联调和验收。

### 34. Mini-Drop 的目标用户是谁？

主要用户是需要排查 Linux 服务性能问题的后端工程师、SRE 和性能工程师。典型问题包括 CPU 高、内存增长、I/O 延迟、锁竞争、网络或下游慢，以及 Python、Go、Java、C++ 运行时专项问题。

### 35. 一次诊断怎样从用户请求走到最终报告？

用户在 React 页面描述问题，Go API 完成鉴权并创建 Diagnosis。服务端发现在线 Agent 和新鲜进程快照，签发安全目标 binding。Scope 确认目标和时间窗后，Knowledge RAG 提供取证知识，Skill 提供调查路线先验。

Diagnosis Agent 生成多个可证伪假设，LATS 选择下一分支。工具请求经过 Policy、运行时能力、预算和人工审批后创建 Task。C++ Agent 领取一次 Attempt，调用白名单 Collector 采集数据，并将 Artifact 上传到 MinIO。Python Analyzer 检查样本质量并生成分析结果，Evidence Gate 再把有效结果转换成结构化 Evidence。

Agent 根据 Evidence 做反思和价值回传，决定继续深入、跨域转向、剪枝或停止。满足证据门禁、反证检查、最少轮次和停止条件后生成 VERIFIED 报告；预算耗尽仍无法证明时输出 INSUFFICIENT_EVIDENCE。

### 36. Task、Attempt、Artifact 和 Evidence 有什么区别？

Task 表示用户希望完成的一次采集任务。Attempt 表示某个 Agent 对该任务的一次真实执行，重试时应该新增 Attempt，而不是覆盖第一次失败。Artifact 是某次 Attempt 产生的原始文件或派生结果。Evidence 是 Artifact 经过来源、目标、时间窗、hash、样本质量、分析状态和主张门禁后形成的结构化事实。

分层的目的，是既能保留重试历史，又能证明最终报告到底引用了哪次执行的哪个文件和哪条有效事实。

### 37. 为什么 Artifact 不能直接当作 Evidence？

Artifact 上传成功只能证明文件存在。文件可能为空、没有正样本、采错进程、时间窗不匹配、符号缺失或解析失败。如果模型看到“有文件”就直接下结论，会把无效材料误当事实。因此必须经过质量和主张门禁后，才能成为 Evidence。

### 38. Mini-Drop 为什么不让大模型直接 SSH？

因为模型可能编造目标、命令和参数，也无法可靠控制生产权限、执行预算和审计。Mini-Drop 让模型只提出语义工具请求，服务端再把请求映射为白名单 Collector，并检查目标绑定、Agent 能力、运行时、内核权限、预算和审批。

### 39. 为什么不能只用 PID 标识目标进程？

Linux PID 会被复用。目标进程重启后，同一个 PID 可能已经属于另一个进程。Mini-Drop 的 binding 同时关联 Agent、PID、进程启动时间、命名空间和过期时间。模型只能选择服务端签发的不透明 binding，不能自行编造或修改 PID。

### 40. Knowledge RAG、Skill 和 Evidence 有什么区别？

Knowledge RAG 提供领域知识，例如某种现象通常应该采集哪些指标；Skill 保存经过验证的调查路线和探针顺序；Evidence 才是当前机器、本次诊断中新采集并通过门禁的事实。

RAG 和 Skill 都只能影响“下一步查什么”，不能直接证明本次根因，也不能把历史事故证据搬到当前会话。

### 41. Skill 是怎样检索的？

当前只有十三个内置 Skill，因此没有使用 Elasticsearch、向量数据库或外部 Embedding。候选阶段在 Python 进程内使用 BM25、512 维确定性哈希 n-gram 和领域概念特征，再结合环境、运行时、子系统和 Collector 能力进行硬门禁。

系统先读取轻量目录信息，只有命中后才加载完整 SKILL.md，并校验路径、编码、大小、章节和 SHA-256。这叫渐进式披露，可以减少上下文长度，也能防止未命中的 Skill 指令进入模型上下文。

### 42. Skill 命中以后，为什么还要重新采集？

Skill 只说明过去验证过的调查路线，不代表当前事故根因相同。如果直接复用旧结论，就会把先验当事实。即使 Skill 命中，系统仍必须对当前目标执行新的 Tool Call，产生新的 Task、Artifact 和 Evidence。

### 43. LATS 在项目中解决什么问题？

它解决单链 Agent 容易沿第一条假设一路跑偏的问题。系统保留多个候选假设，用 UCT 或显式 PUCT 平衡利用和探索，选择下一条值得取证的分支。工具返回真实观察后，系统进行反思和奖励回传，再决定深入、转向或剪枝。

LATS 的价值是管理多个假设的搜索过程，不是让模型输出一棵好看的静态树。

### 44. 页面上的 LATS 为什么有七个步骤？

论文通常描述为 Selection、Expansion、Evaluation、Simulation、Backpropagation 和 Reflection 六个阶段。Mini-Drop 为了让工具执行更容易理解，把 Simulation 拆成“行动”和“观察”，所以页面显示：选择、扩展、评估、行动、观察、反思、价值回传。算法含义没有改变。

### 45. UCT 和 PUCT 是什么？

UCT 的核心是“平均回报加探索奖励”：既优先已经表现好的分支，也给访问较少的分支机会。PUCT 在这个基础上加入候选 Prior，使先验更高的分支可以更早被探索。

Visits、Value、Mean Value、Prior 和 UCT/PUCT 分数只用于决定下一步调查顺序，不是 Evidence，也不是最终根因的可信度。

### 46. 为什么既使用 LangGraph，又使用 LATS？

LangChain create_agent 负责模型和语义工具循环，LangGraph 负责线程、节点调度、Checkpoint 和可恢复执行。LATS 负责多个假设之间的搜索、反思和价值回传。Mini-Drop 自己的领域服务负责目标绑定、权限、预算、工具白名单、Evidence Gate 和业务持久化。

三者解决的问题不同，不是重复实现三套 Agent 框架。

### 47. 为什么实时诊断不能称为完整 LATS？

真实 CPU、队列、锁和网络状态会随时间变化，Profiler 本身也会推进时间并影响系统。执行完一个兄弟分支后，无法把整台机器恢复到完全相同的起点再执行另一个分支。因此实时诊断只能称为 BUDGETED_LATS，也就是预算约束的渐进式真实搜索。

完整 FULL_LATS 只在冻结 Observation Provider 中验证。冻结回放可以在每个兄弟 rollout 前恢复相同快照，但它不会创建真实 Tool Call、Task、Artifact、Evidence 或 Report，只能证明搜索算法和恢复逻辑。

### 48. 假设没有被支持时，系统怎样处理？

如果 Evidence 明确否定假设，就记录反证、降低该分支奖励，并剪枝或转向其他证据域。如果 Evidence 有效但既不支持也不反驳，就标为中性，选择信息量更高的新工具。如果证据有效但质量或覆盖有限，就保留限制并补充独立证据。

只要还有预算，系统可以从 CPU、内存、I/O、网络、运行时和依赖等未覆盖领域继续扩展。

### 49. 采集失败能不能说明假设不成立？

不能。Agent 离线、权限不足、采集器不兼容、Tool Call 失败或审批拒绝，只能说明本次不可观测。科学反证需要真实 Evidence 明确否定假设。把工具失败当反证，会让系统错误排除真正的根因。

### 50. 诊断有哪些终态？

VERIFIED 表示证据通过门禁，并且报告引用本次 Evidence。INSUFFICIENT_EVIDENCE 表示在工具、时间或搜索预算耗尽后仍无法证明根因。会话还可能因为执行错误或用户操作进入 FAILED 或 CANCELLED。

单个分支证据不足不等于整个 Diagnosis 立刻结束；如果仍有预算和未覆盖证据域，就应该继续调查。

### 51. 如何防止 Agent 第一轮直接猜答案？

服务端设置最少有报告诊断轮次，要求支持证据之后继续进行反证检查和交叉验证。一个分支失败后会跨域扩展。最终停止由服务端的 Evidence、最少轮次、工具预算和搜索停止条件共同决定，不由模型说一句“已经完成”决定。

### 52. Mini-Drop 的安全设计有哪些？

第一，目标使用包含 Agent、PID、启动时间、命名空间和过期时间的 binding，防止 PID 复用和模型伪造目标。第二，模型只能选择允许的语义工具，实际 Collector 由服务端映射。第三，工具还要通过运行时、Agent capability、内核权限、预算和审批门禁。第四，Control 和 Agent 使用 mTLS。第五，Artifact 使用短时、限定对象的上传地址，Agent 不持有长期对象存储管理员密钥。

### 53. Mini-Drop 怎样保证重试和恢复的一致性？

浏览器重试、SSE 重连和 Worker 重启可能造成重复请求，因此系统使用 idempotency key、effect key 和唯一约束，避免重复创建 Task、节点和事件。

Agent 领取任务时获得租约，失联或超时后可以创建新的 Attempt 接管。事务 Outbox 保证状态入库和事件发布不会一边成功一边丢失。人工干预通过 expected_version 做 CAS 校验，拒绝用旧树版本覆盖新状态。

### 54. Checkpoint 降级是怎么回事？

生产环境期望使用 PostgreSQL 保存 LangGraph Checkpoint。如果数据库连接或初始化失败，Worker 可以为了保持业务服务而降级到进程内存，但状态必须显示 DEGRADED，并分别展示 requested backend 和 actual backend。

降级到内存后，Worker 重启可能丢失模型短期消息，但已经持久化到 PostgreSQL 的 Diagnosis、领域事件、Evidence 和 Report 不能一起消失。

### 55. SSE 为什么还需要轮询兜底？

EventSource 可能因为反向代理缓冲、空闲超时、会话过期或网络切换而断开。页面先尝试 SSE 自动重连，暂时不可用时使用低频轮询重新读取服务端状态。领域事件和数据库是事实源，SSE 只是实时投影通道。

### 56. Mini-Drop 当前自动化测试到什么程度？

当前基线是 Python 447 passed、3 skipped；Web 有 30 个测试文件、126 项测试通过；Go 全包测试通过；OpenAPI 有 72 个 method/path 对通过。

这些结果证明状态机、接口、解析、权限和页面合同符合预期，但不能单独证明所有 Linux Collector 都能在真实机器工作，也不能证明根因准确率。

### 57. 两套 540 条评测集分别测什么？

diagnosis-v2 测 Skill 是否召回正确路线，以及不该激活时能否安全拒绝。它有 540 个新提示词 Case，当前 506 个通过，但这不是根因准确率。

root-cause-v1 由 21 个可执行故障合同生成 540 条确定性变体，要求在固定两次工具预算内到达关键采集器，并且预测根因 ID 与私有真值一致。关闭 Skill 的 Top-1 是 42.78%，开启 Skill 是 70.37%。固定 500 组同题同预算对比是 41.20% 和 68.00%。

这些都是受控回放，不是 540 次公网 Linux 真机故障注入。

### 58. Mini-Drop 哪些能力完成了真实 Linux 验收？

Python 源码热点、Go CPU 热点和 C++ CPU 热点已经完成真实 live E2E，能够产生新的 Task、Attempt、Artifact、Evidence 和 Report。持续 perf 也完成了 60 秒、4 个窗口的专项验收；独立 eBPF Campaign 获取到非零真实 I/O 样本，并验证了停止和清理。

Java GC 已经能自动发现并绑定真实 JVM，但最近一次完整推进仍发生超时，不能说全链路通过。其余故障广场场景目前主要证明故障注入和合同存在，不能说 21 个场景都完成根因诊断验收。

### 59. Skill A/B 能不能证明性能或准确率提升？

离线 500 组同题同预算受控回放可以证明固定合同下的路线策略差异。真实页面 A/B 可以证明 AUTO 和 DISABLED 两条链都实际运行，并且 Skill 能改变首个工具。

但单次顺序运行不能证明普遍提速。严格 A/B 还需要相同目标、时间窗和负载，确保每个实验臂前故障被重置，并进行随机化、足够样本量、异常样本处理和统计检验。

### 60. Mini-Drop 的 Skill 是怎样“自进化”的？

当前的自进化是受控发布流程：从成功报告和用户反馈中生成候选 Skill，进行静态校验、冲突检测和离线评测，再由人工审批后发布。上线后根据反馈和评测结果隔离或回滚。

系统不会让模型在线自动修改生产 Prompt、代码和权限，也没有自动随机分流和统计发布平台。因此应称为受控演进，不是完全自治的自修改系统。

### 61. Mini-Drop 最困难的工程问题是什么？

最困难的不是让模型提出几个原因，而是把不稳定、容易猜答案的模型约束成安全、可恢复、可审计的诊断系统。

目标不能被模型伪造，工具不能越权，失败不能误当反证，上传文件不能自动当证据，重试不能重复产生副作用，服务重启后状态要能恢复，最终报告只能引用当前会话通过门禁的 Evidence。这些约束共同构成项目的核心工程难点。

### 62. Mini-Drop 简历上的历史指标怎样解释？

简历中的指标属于较早版本：完成 12 容器云端部署和 3 个 Agent 在线验收；一次白名单 OTel CPU Campaign 中，目标 CPU 从 0.30% 上升到 96.33%，停止后回到 0.29%，输出 SELF_CODE_CPU_HOTSPOT，置信度 0.91 并与 Oracle 一致；当时有 63 项相关回归和 30 场景乘 3 策略的 90 条记录。

这些数字只能按对应历史验收材料解释。当前仓库已经增加 LATS、Skill、540/500 评测和更多 live E2E，不能把两个版本的数字拼成一次实验，也不能用当前测试替历史压测背书。

### 63. Mini-Drop 当前还没有验证什么？

Java GC 完整诊断仍未通过，其他未逐项验收的故障场景不能宣称全链路完成。真实页面 Skill A/B 还不是随机化统计实验。FULL_LATS 只在冻结回放中成立，实时环境仍是 BUDGETED_LATS。所谓 Skill 自进化仍依赖离线评测和人工发布，没有在线自动更新生产策略。

## 三、两个项目的横向问题

### 64. 两个项目有什么关系？

两个项目都不是简单封装一次模型调用。AGI-saber 更关注私有知识检索、工具执行、失败降级和 Agent 质量评测；Mini-Drop 更关注真实系统取证、安全目标绑定和证据驱动的根因搜索。

AGI-saber 建立了 RAG、Trace、熔断、降级和 DAG 调度能力；Mini-Drop 把这些工程思想放到风险更高的性能诊断场景中，再通过 Evidence Gate、LangGraph Checkpoint 和 LATS 约束模型。

### 65. 两个项目最大的共同点是什么？

共同点是让大模型只负责不确定性的判断，把事实、权限、状态和副作用交给确定性程序控制。同时都强调可观测、可降级、可恢复和可评测，不用一段看起来合理的自然语言代替工程证据。

### 66. 两个项目最大的区别是什么？

AGI-saber 的主要事实来源是用户文档，核心问题是能否召回正确内容并忠实引用；Mini-Drop 的主要事实来源是当前机器的真实采集，核心问题是下一步应该采什么证据，以及这些证据能否支持或反驳根因。

### 67. 面试官问“这些是不是套壳项目”，怎么回答？

如果只调用一次模型并返回文本，确实很接近套壳。但两个项目都增加了模型之外的确定性工程合同。

AGI-saber 有文档版本、父子分块、多路召回、RRF、Rerank、无答案门禁、引用、Trace、熔断、索引重建和评测闭环。Mini-Drop 有安全目标 binding、白名单 Collector、Task/Attempt/Artifact/Evidence 分层、Evidence Gate、租约、Outbox、Checkpoint、LATS 搜索和真实 Linux 验收。核心价值在这些可验证的工程边界，而不是聊天界面。

### 68. 如果面试官问“你到底负责了什么”，怎么回答？

可以回答：“我参与团队全栈开发，但个人重点不是把所有模块都说成自己独立完成。AGI-saber 中我重点负责 Python/FastAPI 后端、RAG 质量链、Agent Runtime 和评测；Mini-Drop 中我重点负责 AI 诊断方案调研、假设搜索与推理编排、Evidence 约束和全链路联调验收。对于底层 Collector、前端或部署，我能解释协作接口和整体链路，但不会把所有代码都认领成个人独立成果。”

### 69. 面试官问“哪些结果真的验证过”，应该怎样组织？

先分四层回答：源码已实现、自动化测试通过、受控离线回放通过、真实环境 E2E 通过。然后说明每一层能证明什么、不能证明什么。

AGI-saber 当前 274 项自动化测试通过，但真实 RAG 业务评测集仍然不足；十二条 Replay 主要证明评测闭环。Mini-Drop 除自动化测试和 540/500 受控回放外，还有 Python、Go、C++、持续 perf 和 eBPF 的真实 Linux 验收，因此可以证明这些链路确实产生了新的采集、证据和报告，但不能外推到 Java 和全部二十一个故障场景。

### 70. 不会回答时怎样避免越说越错？

先说：“我先把当前确定实现的部分和设计目标分开。”然后只讲自己确认过的源码事实。如果不记得精确参数，可以先讲参数的作用和取舍，再说明具体默认值需要看配置。不要编造模型、数据集、线上指标或个人职责。

## 四、最后速记

### 71. AGI-saber 一句话总纲是什么？

用父子块和混合检索把私有文档变成可引用答案，再用可恢复执行、降级和评测闭环保证系统不只“能回答”，还能够定位、回归和解释失败。

### 72. Mini-Drop 一句话总纲是什么？

Mini-Drop 不是让 AI 猜根因，而是让 AI 在安全、可恢复、可审计的搜索中选择下一项证据，再由真实采集和 Evidence Gate 决定结论。

### 73. 明天面试前最应该背什么？

先背两段项目介绍，再画两张图：AGI-saber 的“文档入库到带引用回答”，以及 Mini-Drop 的“用户请求到 Evidence 报告”。然后重点练父子块、RRF 与 Rerank、TaskGraph、Task/Attempt/Artifact/Evidence、不可观测与反证、FULL_LATS 与 BUDGETED_LATS、测试与真实验收边界。
