# Collection / analysis contract V2

Existing protobuf field numbers and V1 task kinds remain valid. Task metadata
is authoritative in `task-kinds.json`; COMPOSITE is API orchestration only.

`tasks.params` retains pid/duration_seconds/frequency_hz/scope and adds:

```json
{"target":{"type":"process","pid":123,"start_time_ticks":0},"budget":{"max_file_bytes":33554432,"max_address_space_bytes":8589934592,"max_cpu_seconds":120,"max_processes":32,"max_concurrency":1},"options":{}}
```

Targets may be process, host or container. Container targets carry runtime
docker/containerd, a 12..64 hex container_id and optional container_pid. Agent
maps to a host-visible PID, validates UID/namespace policy, then pins Linux
start_time_ticks and rechecks before/after execution. PID 1, unapproved UIDs,
unknown runtimes, stale start times and path/argument injection are rejected.
Host resource snapshots are explicitly authorized separately.

TaskDesc fields 11..18 carry target/budget/options and the selected raw
format/name/content type/pipeline; typed payload fields 20..29 are populated
from the same options. Field 30 is optional task-scoped additional PUT grants.
The primary RAW still uses fields 7/8 and ResultRequest.artifact=5. An auxiliary
target.elf BINARY may be uploaded for native symbolization and is required for
BOLT optimization; no object storage access key is delivered to Agent.

ArtifactInfo adds format=6, metadata_json=7 and kind=8. ResultRequest adds
runner_metadata_json=9 and auxiliary artifacts=10. The server validates all
object keys against this attempt's issued grants, file/type/hash/size budgets,
and atomically persists artifacts, collection state, events and AnalysisJob.
Binary inputs must never be decoded as folded text.

Trace JSONL uses schema_version=1, event, time_ns, pid, tid, comm,
bytes/duration_ns/operation/stack when actually available. Memory records use
alloc/free/pagefault/mmap events with address/size/major as available. No field
is synthesized if unavailable. Resource JSON is schema_version=1, samples[]
with timestamp_ns/cpu_percent/rss_bytes/vms_bytes/read_bytes/write_bytes/
threads/fd_count. Script JSON is schema_version=1, template, exit_code, stdout,
stderr, duration_ms. Script templates are compiled allowlisted diagnostics.

gperftools/jemalloc collection requires an instrumented target exposing a
per-PID Unix control socket under the administrator configured control root.
SO_PEERCRED must match the selected target. Commands start/stop/snapshot call
the real native profiling APIs; arbitrary shell and debugger injection are
not supported. Profiles are transported as bounded binary responses.

DB additions coordinated with API migration 002: artifacts.format text and
metadata jsonb; agents.capability_details jsonb; agent_events with unique
event_id and agent_id/type/payload/occurred_at/created_at. Agent capability
details expose actual path hash/version/probe/permission failures. FetchData
is bounded control-plane diagnostics (resources/capabilities/processes/events),
not arbitrary filesystem access or large raw profile transfer.

## Collection manifest and terminal upload authorization

Current V2 dispatch grants include the fixed `runner.log` diagnostic and
`collection-manifest.json` collection receipt, in addition to any catalog
`target.elf` attachment. The receipt uses `kind=MANIFEST`,
`format=collection_manifest_v1`, `content_type=application/json` and
`max_file_bytes=65536`. Its key is exactly
`manifest/tasks/{task_id}/attempts/{attempt_number}/collection-manifest.json`.
Existing protobuf fields carry this grant; no field numbers change.

The Agent creates the collection receipt after successful RAW/BINARY PUTs,
persists its bounded journal and uploads it before successful NotifyResult.
The receipt records task/attempt/kind, Agent/Runner/tool versions, artifact
names/keys/sizes/SHA-256, collection start/end and upload completion times,
and an allowlisted parameter summary without credentials or signed URLs.
This is separate from the Analyzer's later `manifest.json`. N-1 descriptions
without this optional grant retain their existing collection behavior.

Termination revokes RAW/BINARY/MANIFEST grants and every `put_url`. Only the
six fixed authorization fields for `runner.log` survive briefly for the
current attempt's 120-second terminal LOG grace; a collection manifest cannot
be added after termination or from an old attempt. Task deletion and retry
also revoke that remaining authorization.
