# Kubernetes delivery

`resources.json` is generated by `python scripts/render_kubernetes.py`. It is a native Kubernetes List, accepted by kubectl and kustomize. All four modules have independent Deployments; API/Server/Web and short analysis workers have multiple replicas, PodDisruptionBudgets, spread preferences and rolling updates. Large heap jobs use a separate queue and labelled node pool with explicit CPU, memory and ephemeral disk limits. These manifests require an actual cluster; the 2-vCPU production machine continues to use Compose.

Before applying:

1. Push signed release images to your private registry; set images with `kustomize edit set image`. Keep N/N-1 compatible Server/Agent images during upgrades.
2. Provision PostgreSQL and S3-compatible storage in independent failure domains. Supply a TLS-verified PostgreSQL DSN, S3 endpoint and trusted CA; do not create a single in-cluster database and describe it as HA. Configure the endpoints in `drop-config`.
3. Create Secret `drop-runtime` with database_url, s3_access_key, s3_secret_key, admin_username, admin_password and alert_webhook_token from a secret manager. Create separate `drop-server-tls` and `drop-api-tls` Secrets containing ca.crt and the appropriate leaf cert/key. Runtime pods never receive the CA signing key or database owner credential.
4. Run the `drop-api:<release> migrate` command as a separate Job using the database owner credential. Apply runtime database grants and append-only audit permissions after migrations. Do this before starting the new images.
5. Label dedicated heap nodes `drop.io/high-memory=true`; optionally taint them with `drop.io/high-memory=true:NoSchedule`. Their declared budget is 4GiB memory and 8GiB temporary disk per worker, above this single server's capacity.
6. Deploy Prometheus/OTel from your cluster platform or adapt `deploy/observability`. Configure ServiceMonitors/PodMonitors to scrape each replica rather than a load-balanced Service.
7. Apply `kubectl apply -k deploy/kubernetes`, inspect rollout and readiness, then publish Web using an Ingress with a trusted certificate. No database, object storage or gRPC service is exposed publicly.

`agent-daemonset.yaml` is separate because business process inspection needs node-specific permission. Pre-provision `/etc/drop/tls` on each approved node with a client certificate whose CN is `drop-agent-<node-name>`, and install the perf seccomp profile at `/var/lib/kubelet/seccomp/drop-agent-perfmon.json`. Do not distribute one client identity to all nodes. The base DaemonSet has no runtime socket and no unrestricted privileged container; container-runtime access is an additional reviewed profile. `deploy/systemd` supports ordinary hosts.

The DaemonSet separates the UID10001/capability-free Agent from a root collector-helper sidecar. Only the Agent receives the three individual TLS files. The helper receives its typed IPC socket, root-only cache and a separately mounted incoming directory on the same pre-provisioned 2GiB filesystem. Run the host spool preparation before deploying; `Directory` hostPath types reject an absent mount instead of creating an unbounded host-root fallback. The existing optional node-inspection `hostPID` policy is unchanged: this file is for approved collection nodes, not the Aliyun Compose profile. Its helper defaults to PERFMON/SYS_PTRACE/DAC_READ_SEARCH. BPF capability/tracefs access and container-runtime resolution require a separate explicitly selected node policy. Host network namespace permissions are not added; attach mechanisms that require a target's network namespace can still be unavailable in this profile.

Java/native cooperative collectors run as the same UID as the ordinary Agent and write RAW under bounded incoming. Native schema2 adapters also put intermediate scratch in `/run/drop-helper-incoming/native-control`, owner10001/mode0700; the old unbounded `/tmp` adapter protocol is rejected. This does not authorize arbitrary different-UID targets.

Generated runtime Secret references use individual read-only `subPath` mounts so Core's strict generic `*_FILE` reader sees regular files. These values are loaded at startup; rotate the Secret and perform a controlled rollout. Do not assume a projected Secret symlink or a Secret update silently changes already loaded credentials. TLS loading keeps its own documented file behavior.

The shared socket is ephemeral but the Agent journal and helper cache use separate node paths so container restarts do not silently recollect a task. The init container only adjusts ownership of the Agent's fixed work directory. The native helper and full cluster behavior still need runtime qualification; the latest strict Kubernetes1.34.1 schema check covered21 resources with zero errors/skips.

The actual cluster must still pass node loss, database failover, storage failover, certificate rotation, backup restore and rolling-upgrade exercises before an HA claim is made. Manifests and local schema validation are not evidence of those infrastructure outcomes.
