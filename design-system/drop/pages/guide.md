## 从问题到设计

原页面的浅蓝大横幅占用首屏，却没有说明下一步操作；连续等权卡片削弱了阅读顺序，窄屏文字和内容边界也需要复核。新版采用技术手册的编辑式结构：明确的双行标题、证据闭环图、四段目录、可切换流程、现象索引、可展开的结果边界、开始调查入口。图示表达流程关系，不伪造采样曲线或业务指标。

四个阶段分别讲清楚输入、操作、留下的证据和判断边界。源码修复注明仅适用于已绑定仓库的隔离副本；复测结果不直接等同于因果成立。只有有写权限的用户能看到调查和新建入口。

## 八项复审

| 维度 | 实现与复审 |
| --- | --- |
| 排版 | 36–55px 主标题、明确的段落层次、14px 主要说明文字。中文指定系统无衬线 fallback；CDP 实测 Windows Chromium 使用 Microsoft YaHei UI，标题为 Bold、正文为 Regular。其他系统遵循各自 fallback，未声明已逐平台实机检查。 |
| 留白 | 内容宽度上限 1240px；章节以分隔线与节奏区分。手机缩短首屏图示和段间距，让流程入口更早出现。 |
| 视觉层级 | 一项主操作，四阶段只选中一项；场景用行式索引，FAQ 用原生 disclosure，避免所有内容都装进等权卡片。 |
| 色彩 | 最新使用云蓝、冷灰、深蓝灰文字及白色面板；成功绿与错误红保持语义，不以颜色作为唯一状态提示。 |
| 动效 | 短距离入场和面板过渡，只使用 transform/opacity；尊重 prefers-reduced-motion，不引入滚动劫持。 |
| 微交互 | 原生按钮、aria-pressed、受控区域标签、可见焦点、Enter/Space、FAQ 键盘展开、锚点定位和明确链接目标。 |
| 响应式 | 实测 1440/1280/1024/768/375/320 六种宽度；四个阶段共享自然高度的 grid 区域，实测四种宽度中切换时下方章节位移均为 0px，无裁切。 |
| 原创性 | 围绕性能诊断的证据闭环制作代码图示与流程阅读结构，使用已有 Phosphor 图标，没有套用消费品牌落地页或复制获奖网站布局。 |

实际完成三轮复审：修复图示节点和 FAQ 图标溢出；修正中文字体回退、手机留白和正文大小；改用自然预留高度解决切换跳动，最后消除 320px 标题孤行。独立复审查看了最终桌面与手机截图，未发现阻止发布的实质问题。这是本次验收判断，不声称获得奖项或不存在任何未来改进空间。
