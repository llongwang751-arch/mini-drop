# I/O 延迟分层诊断

## 目标
定位服务变慢是否由目标进程 I/O、文件系统、块设备或同宿主机其他进程造成。

## 输入契约
- 必填：`agent_id`、`pid`、`environment`、`start_time`、`end_time`。
- 可选：磁盘设备、挂载点、容器 ID 和基线窗口。

## 适用与停止条件
- 适用：iowait、磁盘 await、写入量或文件系统延迟异常。
- tracefs/eBPF 权限不可用时显式降级；无进程与设备关联证据时不建立目标代码根因。

## 取证顺序
1. 比较吞吐、iowait、设备利用率和延迟分布的基线与故障窗口。
2. 采集目标 PID 的读写量、阻塞状态、文件描述符和主要文件路径。
3. 使用白名单 eBPF 探针或受控内核工具观察 I/O 延迟直方图。
4. 对比同宿主机进程，判断是否存在噪声邻居。
5. 停止故障或修复后采集恢复窗。

## 结论门槛
- 目标进程根因：进程读写与设备延迟同窗异常，恢复后同步回落。
- 噪声邻居：设备繁忙但目标进程读写稳定，其他进程贡献主要 I/O。
- 只有设备繁忙、没有进程归属证据时保持待验证。

## 必需证据与反证
- 支持证据：设备指标、进程 I/O、延迟分布、文件/调用路径、恢复窗。
- 反证：目标进程无 I/O、异常来自网络文件系统、探针丢样或权限降级。

## 安全边界
只使用白名单探针和受控故障开关；任何故障注入必须在 `finally` 阶段恢复。

## 输出契约
输出 `root_cause`、`scope`、`confidence`、`evidence_refs`、`counter_evidence_refs`、`limitations` 和 `next_action`。

## 回归门禁
覆盖目标写放大、噪声邻居、权限降级和网络盘误导反例；必须验证恢复窗且不能把空探针结果当作正常。
