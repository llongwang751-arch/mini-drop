# CPU 热点循证诊断

## 适用场景

目标服务 CPU 持续升高，并且已经确认目标 Agent、PID 和故障时间窗。

## 取证顺序

1. 采集系统与进程 CPU 指标，确认异常是否与目标进程同窗出现。
2. 对目标 PID 执行受控 perf 采样，生成火焰图和热点函数 TopN。
3. 检查热点是否集中在少数业务函数，并寻找内核态、锁等待等反证。
4. 停止受控故障或应用修复后重复采集，确认 CPU 和热点占比回落。

## 结论门槛

- 必须同时引用基线、故障和恢复阶段的证据。
- 只有 CPU 上升而没有有效调用栈时，不建立代码热点根因。
- 采集器降级、样本为空或 PID 已退出时，返回证据不足并切换取证方向。

## 安全边界

只允许调用注册过的只读采集工具；perf 等高开销采集必须经过审批并限制持续时间。
