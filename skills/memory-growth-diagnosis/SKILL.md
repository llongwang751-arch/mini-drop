# 内存持续增长诊断

## 适用场景

目标进程 RSS、PSS 或堆内存持续增长，需要区分缓存增长、对象保留和真实泄漏。

## 取证顺序

1. 在连续时间窗采集 RSS、PSS、Swap 和内存映射。
2. 对语言运行时采集堆或对象保留信息，核对增长对象及其引用链。
3. 检查 GC、缓存容量、请求量变化等替代解释。
4. 停止受控故障或执行修复后复测，确认增长斜率消失或内存回收。

## 结论门槛

- 单点 RSS 高不等于内存泄漏，必须有持续增长证据。
- 必须提供对象、映射或堆增长证据之一，并引用恢复窗口。
- 无法采集语言级证据时，只能输出内存压力或疑似对象保留，不得硬判泄漏。

## 安全边界

默认使用低开销趋势采集；堆转储等高风险动作必须审批，且不得自动在线上执行。
