# 内存持续增长诊断

## 目标
判断内存是否真的持续增长、增长发生在哪里，以及停止负载或修复后能否恢复。

## 输入契约
- 必填：`agent_id`、`pid`、`environment`、`start_time`、`end_time`。
- 可选：运行时类型、堆上限、缓存容量、请求量和发布版本。

## 适用与停止条件
- 适用：RSS/PSS/堆持续增长、Swap 增加或出现 OOM 风险。
- 单点 RSS 高、容器刚启动或请求量同步增长时，不得直接判定泄漏。
- 无连续窗口或 PID 已退出时返回证据不足。

## 取证顺序
1. 连续采集 RSS、PSS、Swap、匿名映射和文件映射，计算增长斜率。
2. 对语言运行时采集堆、对象类型或引用保留信息。
3. 对齐请求量、缓存容量、GC 次数和暂停时间，排除正常缓存和流量增长。
4. 停止故障或应用修复后复测，确认增长斜率消失或内存回收。

## 结论门槛
- 真实泄漏：连续增长，存在对象或映射保留证据，修复后增长停止或内存回收。
- 缓存增长：内存随缓存容量增长并在上限附近稳定。
- GC 压力：分配率、GC 次数/暂停与延迟同步变化，但对象可回收。
- 缺少对象或映射证据时，只能输出“内存压力/疑似保留”。

## 必需证据与反证
- 支持证据：RSS/PSS 趋势、对象/映射增长、GC 或缓存指标、恢复窗。
- 反证：增长随流量变化并稳定、采样窗口过短、数据跨进程重启拼接。

## 安全边界
默认使用低开销趋势采集；堆转储和全量对象扫描必须审批，不得自动在线上执行。

## 输出契约
输出 `root_cause`、`confidence`、`growth_rate`、`evidence_refs`、`counter_evidence_refs`、`limitations`、`next_action`。

## 回归门禁
正例覆盖对象保留、匿名映射增长和无上限缓存；反例覆盖缓存预热、流量增长和短时 GC 波动。运行时能力缺失时必须降级，不生成虚构对象名。
