# 下游依赖延迟定位

## 适用场景

入口服务延迟升高，需要判断问题来自自身资源、网络链路还是下游服务。

## 取证顺序

1. 检查入口服务 CPU、内存和 I/O 是否同步异常。
2. 对齐请求耗时、下游调用耗时和错误率。
3. 检查下游服务健康状态以及网络延迟、重传等证据。
4. 移除受控下游延迟后复测，确认入口服务响应恢复。

## 结论门槛

- 本机资源稳定、下游耗时上升且恢复后回落，三项同时满足才建立依赖根因。
- 只有入口 P99 升高而缺少调用链证据时，保持待验证。
- 多个下游同时异常时，继续定位共同网络或宿主机问题。

## 安全边界

诊断只读取已注册服务拓扑和遥测；变更路由、重启服务等修复动作必须人工确认。
