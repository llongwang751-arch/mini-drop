# C++ 运行时循证诊断

## 目标
区分 C++ 业务计算热点、互斥锁竞争、同步 I/O、内存压力和网络等待，并把函数级结论绑定到本次采集的原始产物。

## 输入契约
- 必填：`agent_id`、服务端证明的进程绑定、`environment`、`start_time`、`end_time`。
- 可选：二进制版本、构建标识、符号表状态、请求延迟、吞吐与基线窗口。
- 不接受模型猜测 PID 或可执行文件；进程身份、启动时间和 Agent 必须与当前快照一致。

## 适用与停止条件
- 适用：问题中明确出现 C++、cpp、CXX、原生进程或原生二进制，并伴随 CPU 升高、吞吐下降、延迟上升、疑似锁竞争或 syscall 阻塞。
- 不适用：只有“系统”“调用”“服务变慢”或“自动选择取证”等通用描述，且没有 C++/原生运行时身份；此时先使用通用诊断路线，不能仅凭类别标签激活本 Skill。
- 目标退出、时间窗错位、样本为空、产物校验失败或二进制身份变化时停止强归因。
- 符号缺失时允许报告地址级热点并建议补充符号，不能伪造函数名。

## 取证顺序
1. 对已绑定目标执行短时 perf 采样，先识别用户态计算、锁、系统调用或等待方向。
2. 补采主机与进程系统指标，确认 CPU、运行队列、上下文切换、I/O 或内存异常与目标同窗发生。
3. 短样本不足时执行有预算的持续采样，验证热点是否稳定，并主动寻找首要假设的反证。
4. 关闭故障后复测恢复窗口；新证据否定当前方向时，重新规划到锁、I/O、内存或网络分支。

## 结论门槛
- 计算热点要求目标 CPU 同窗升高、perf 样本集中在稳定调用路径且恢复窗回落。
- 锁竞争要求 mutex/futex 栈、等待或上下文切换证据共同支持。
- I/O 或网络等待要求系统调用路径、等待指标和低于预期的本地计算占比共同支持。
- 只有单次采样、符号缺失或缺少反证时，必须降低置信度并保留限制。

## 必需证据与反证
- 支持证据：本次 perf 原始产物与 TopN、系统指标、目标身份、故障窗口和恢复窗口。
- 反证：样本分散、目标 CPU 正常、等待由其他进程主导、停止故障后现象不恢复。

## 安全边界
- 只调用注册的只读采集工具，不执行任意 Shell、重启、信号发送或业务参数修改。
- perf 必须受持续时间、频率、并发和产物大小预算约束；禁止对未绑定进程扩散采样。
- Skill 只提供取证路线先验，不能复制旧案例结论、Evidence、评分或报告文本。

## 输出契约
输出 `root_cause`、`confidence`、`evidence_refs`、`counter_evidence_refs`、`limitations` 和 `next_action`；函数级归因必须引用本次 perf Evidence，符号缺失必须显式标注。

## 回归门禁
- C++ CPU 正例应优先选择 perf，并从真实 Artifact 生成 Evidence。
- 锁竞争、同步 I/O、内存压力和下游等待反例不得误判为纯计算热点。
- 短样本不足时允许有界持续采样，但必须记录预算与停止原因。
- Skill 开启组只允许缩短正确路线选择，关闭组必须独立规划并重新采集。
