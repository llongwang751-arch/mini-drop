# Go 运行时循证诊断

## 目标
区分 Go 业务计算热点、运行时调度或锁等待、系统调用与下游网络等待，并把结论绑定到本次采集的原始产物。

## 输入契约
- 必填：`agent_id`、服务端证明的进程绑定、`environment`、`start_time`、`end_time`。
- 可选：服务名、Go 版本、发布版本、请求延迟与基线窗口。
- 不接受模型猜测 PID；进程身份、启动时间和 Agent 必须与当前快照一致。

## 适用与停止条件
- 适用：Go 服务 CPU 升高、吞吐下降、延迟升高、goroutine 堆积或疑似阻塞。
- 进程退出、pprof 未启用、样本为空、时间窗错位或产物校验失败时停止强归因。
- Go 栈不能解释宿主机异常时转入系统 perf 路线，并明确记录降级原因。

## 取证顺序
1. 对已绑定的 Go 进程采集 pprof，观察 CPU、阻塞和 goroutine 调用路径。
2. 补采主机与目标进程系统指标，确认异常确实与目标同窗发生。
3. pprof 不能解释现象时，受控执行 perf，区分内核、调度、锁和系统调用开销。
4. 主动寻找与首要假设冲突的证据，并在关闭故障后复测恢复窗口。

## 结论门槛
- 计算热点要求目标 CPU 同窗升高、pprof 样本集中且恢复窗回落。
- 锁或调度问题要求等待栈、goroutine 状态与上下文切换共同支持。
- 网络等待要求请求时延、等待调用链与低 CPU/非计算热点共同支持。
- 只有一次采样或缺少反证时，报告必须保留限制并降低置信度。

## 必需证据与反证
- 支持证据：pprof 原始产物与 TopN、系统指标、目标身份、故障及恢复时间窗。
- 反证：样本分散、目标 CPU 正常、主要时间消耗在外部等待、停止故障后指标不恢复。

## 安全边界
- 只调用注册的只读采集工具，不执行任意 Shell、重启或业务参数修改。
- pprof 与 perf 必须受持续时间、采样率、并发和产物大小预算约束。
- Skill 只提供取证路线先验，不能复制旧案例的结论、Evidence 或评分。

## 输出契约
输出 `root_cause`、`confidence`、`evidence_refs`、`counter_evidence_refs`、`limitations` 和 `next_action`；函数级结论必须引用本次 pprof 或 perf Evidence。

## 回归门禁
- Go CPU 正例应优先选择 pprof，并从真实 Artifact 生成 Evidence。
- 网络等待、锁竞争和同机争抢反例不得误判为 Go 计算热点。
- pprof 不可用时允许受控降级，但必须记录原因并降低置信度。
- Skill 开启组只允许缩短正确路线选择，不得预填关闭组尚未采集的事实。
