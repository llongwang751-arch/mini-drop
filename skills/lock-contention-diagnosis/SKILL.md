# 锁竞争与线程等待诊断

## 目标
定位吞吐下降或 CPU 上升是否由互斥锁、自旋锁、条件变量或 futex 等同步路径导致。

## 输入契约
- 必填：`agent_id`、`pid`、`environment`、`start_time`、`end_time`。
- 可选：线程池大小、并发量、语言运行时和发布版本。

## 适用与停止条件
- 适用：并发升高后吞吐下降、线程阻塞、上下文切换增加或 CPU 忙等。
- 无线程/锁栈、样本仅显示业务计算时，不建立锁竞争根因。

## 取证顺序
1. 采集线程状态、运行队列、上下文切换和 CPU。
2. 采集锁相关调用栈和等待时间，定位同步原语及业务路径。
3. 区分阻塞等待与忙等自旋，检查临界区长度和竞争线程数。
4. 降低并发或拆分临界区后采集恢复窗。

## 结论门槛
- 锁栈样本集中，等待/自旋指标异常，并与吞吐下降同窗。
- 降低竞争后吞吐恢复且锁等待下降。
- 仅 CPU 高、没有同步路径证据时转入 CPU 热点诊断。

## 必需证据与反证
- 支持证据：线程状态、上下文切换、锁栈、竞争规模和恢复窗。
- 反证：业务热点集中、I/O 阻塞、运行队列正常或并发下降后无改善。

## 安全边界
不自动修改线程池、锁实现或进程优先级；变更建议需要人工确认。

## 输出契约
输出 `root_cause`、`lock_path`、`confidence`、`evidence_refs`、`counter_evidence_refs`、`limitations`、`next_action`。

## 回归门禁
覆盖互斥等待、自旋、I/O 阻塞和纯计算热点；相似症状反例必须阻止错误 Skill 迁移。
