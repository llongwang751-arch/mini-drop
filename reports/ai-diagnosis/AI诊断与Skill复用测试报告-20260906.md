## 1. 结论

当前版本已经能在网页上完成一条可审计的 AI 诊断链：从故障广场启动服务端白名单故障，由 AI 自主发现安全目标，执行 LATS 树搜索和真实采集工具，经过产物质量门禁形成证据，再生成引用证据的报告。诊断过程中可以继续对话、补充上下文、质疑假设、改变方向和继续调查；探索树会随事件流动态更新。

2026-09-06 的云端实机验收结果为 **PASS**：同一个 Python 源码热点目标分别运行“关闭技能”和“自动技能”两条全新诊断，两组均完成 4 个真实诊断轮次、4 次工具调用、16 条证据和 4 版报告；火焰图根节点均有 2968 个样本，均识别到 `source_hot_function`，故障停止和恢复校验通过。

本轮同时修复了一个容易误导页面的问题：假设的出生层级不再冒充实际执行轮次。树深度仍然是不可变的结构属性，LATS 第几次选择并执行该节点则单独记为诊断轮次。回溯到同层兄弟节点时，页面现在会正确显示第 3、4 轮，而不是重复显示第 1 轮。

## 3. 页面现在能演示什么

| 页面能力 | 用户操作 | 页面上能看到的真实性信号 |
|---|---|---|
| 故障广场 | 选择 Python、Go、Java、C++ 的 CPU、内存、I/O、锁、队列等白名单场景并启动 | 场景 ID、持续时间、当前状态、自动停止；浏览器不能提交任意命令、PID 或 URL |
| 新建诊断 | 用自然语言描述症状并让 AI 自主发现目标 | 服务端签发的诊断 ID、绑定 ID、环境和不可变时间窗 |
| 多轮诊断 | 补充上下文、质疑假设、改变方向、继续调查 | 新的人工干预事件、树版本增长、旧假设降权或新分支出现 |
| LATS 探索树 | 展开树并观察节点 | 假设、工具、任务、证据、报告、剪枝、评分和最佳路径；实际轮次与树深度分开 |
| 技能 A/B | 对同一问题创建“关闭技能”和“自动技能”两条会话 | 两个不同的真实诊断 ID、技能激活、工具调用、证据、报告和范围一致性提示 |
| 任务结果 | 从工具节点进入采集任务 | 尝试、产物、完整性、样本数、火焰图和 TopN；空样本会明确失败而不是伪装成功 |

用户消息只是调查上下文，不会自动升级为证据。只有采集器和分析器产物通过完整性、样本质量和支持关系检查后，才能进入报告。

生成器使用固定种子 `20260905` 生成 540 条新问题，公开输入与私有答案分开保存。它调用生产环境使用的混合检索和拒绝门禁，判断“是否应该复用某条技能路线”。

| 指标 | 数量 | 比例 | 含义 |
|---|---:|---:|---|
| 总体通过 | 506/540 | 93.70% | 正例选中指定技能，负例正确弃权 |
| 正例复用 | 334/360 | 92.78% | 具体问题命中私有答案标注的技能 |
| 负例拒绝 | 172/180 | 95.56% | 歧义、信息不足或环境漂移时不激活 |

这组数据不能回答根因服务是否判对、采样是否成功，也不能证明自动技能比关闭技能更快。它只衡量技能检索和安全拒绝，是适合放入持续集成的稳定回归集。

## 7. 火焰图为空问题

旧链路曾把 `perf` 只有表头、折叠栈为空或可视化只有空根节点的情况标成成功。现在同时检查退出状态和内容质量：

- 没有可解析样本：返回 `NO_PERF_SAMPLES`；
- 没有正权重折叠栈：返回 `NO_FOLDED_STACKS`；
- 样本数为 0、没有可渲染函数或可视化为 0 字节：分析失败，不进入证据；
- 历史空产物不会被“补成”火焰图，必须对正在消耗 CPU 的目标重新采集。

本次实机验收的 Python 火焰图根节点有 2968 个样本，因此不是静态占位或空 JSON。

## 8. 8～10 分钟面试演示

1. 打开 <https://120.24.187.205/ai-diagnosis>，进入“验证与 A/B”里的故障广场。
2. 选择“Python 源码热点”，设置 180 秒，点击“启动并诊断”。说明页面只能选服务端白名单场景。
3. 让 AI 自主发现目标，不手填 PID。展示诊断 ID、目标绑定和时间窗。
4. 在主工作台观察第 1～4 轮：假设形成、LATS 选择、工具调用、任务、证据和报告依次出现。
5. 输入“请质疑当前 CPU 假设，并检查 I/O 等待”，展示人工干预节点、树版本增长和方向切换。
6. 从工具节点进入任务结果，展示非空火焰图、TopN、样本数、产物 SHA-256 和证据引用。
7. 回到“验证与 A/B”，对同一问题启动“关闭技能/自动技能”对比。强调两边都是真实诊断，不是前端写死数字。
8. 停止故障并查看恢复状态。最后再展示 540 条路线评测，明确它与实机根因链是两个不同口径。

面试现场不要重启 ECS，不要在阿里云控制台使用强制重启。应用故障由故障广场自动停止；应用版本由容器编排管理，普通页面演示不需要重启整台云服务器。

## 9. 已知限制与下一步

1. 只对一个 Python 源码热点场景做了完整 Linux 实机 A/B，不能外推 21 个场景的总体根因准确率。
2. 两个 A/B 实验臂顺序运行，适合证明真实链路和策略差异，不适合直接比较延迟；严格实验还需要随机顺序、重复样本和显著性分析。
3. 现有故障广场以单机、单进程为主，跨服务因果链仍可接入 OpenTelemetry Demo 级微服务场景。
4. 540 条评测的分类体系来自当前技能目录，不是外部独立基准。
5. 误导或信息不足的负例仍有 8 次误激活，需要继续调整阈值并保留独立回归集。
