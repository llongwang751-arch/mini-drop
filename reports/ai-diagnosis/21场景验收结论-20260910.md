## 未通过的主要原因与后续需要补齐的能力

| 缺口 | 本轮证据 | 需要完成的工作 |
| --- | --- | --- |
| 有具体函数，但缺因果对照 | Python 源码、Go CPU、Java 锁、C++ CPU 等只能形成阶段性发现 | 在相同流量下增加可归属的对照窗口，核验业务指标和候选原因一起变化 |
| 等待型故障仍选择 CPU 采样 | Java 文件写入、C++ 文件写入出现 NO_PERF_SAMPLES | 根据等待症状选择 wall、锁、进程 I/O 或依赖耗时采样，并有明确降级路径 |
| 资源证据没有归属到故障链路 | 主机 I/O、队列、入口饱和及下游延迟不足以单独确认根因 | 增加进程/请求级采集，关联等待资源、队列入口出口和下游请求 |
| 证据没有覆盖全部假设判据 | 多个报告 coverage 小于 1，缺独立反证或对照 | 规划下一次采集时明确指出缺哪个判据，并选择能实际覆盖它的工具 |
| 报告门禁与场景真实原因不完全一致 | Java 下游场景有 VERIFIED 报告，但具体发现不符合验收真值 | 继续保留独立场景真值核对，不能只看会话完成或 VERIFIED 字段 |

这 20 项不能全部称为“判断错误”：其中既有证据不足，也有采集失败和报告不匹配。它们目前都不满足本轮通过标准。
